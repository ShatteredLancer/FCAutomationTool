# 联赛合集预查价与后台调度（27.0.78）

## 现场证据与根因

- 用户提供的27.0.77诊断：一轮grade-plan耗时224,592ms，其中processing112ms、scheduling224,446ms、validation32ms，76个microSteps、13个checkpoint，最后QUOTE_CHANGED。不能把它解释为本地算法计算了224秒。
- 另一个FUTBIN展示报价批次覆盖250版本、266请求、450,994ms。实际production-entry的galleryPlanningPrices会完整传递options，并不是规划参数丢失。
- 详情gallerySetLoader进入时先等待完整池展示报价：没有规划截止且读取展示源，和显式规划共享队列。此前.77只修规划路径，漏了详情自动展示路径。计算默认setTimeout(0)也会受到后台计时器节流。

## 实施边界

1. 详情入口显式autoDisplay；超过64个不同版本时返回deferred空报价，不启动全目录展示查价。界面明确提示按需核价，不伪造价格或fresh状态；小合集自动展示、显式报价/规划仍保留原能力。
2. 生成方案仍按所选主来源、原90秒共享截止及一次有界临期更新；公共服务并发/pending/退避/TTL保持原合同，不提前释放尚未结束的网络工作。
3. 纯计算复用已有协作helper，但Gallery优先用普通MessageChannel任务，避免后台timer节流及原生scheduler.yield连续任务挤压计时器；每次完成关闭两个port。没有MessageChannel才回退原生yield，再回退timer。不改Streamlined helper源码、不改交易或网络等待，不增加后台保活。
4. 账号、材料、报价真正变化/到期仍取消并提示；浏览器真正冻结/系统睡眠仍可能到期，不承诺任意后台状态持续运行。
5. 不变：FSU26.09.10、锁卡/主阵容、审批、总预算/单卡限价、计分规则、Gallery已拥有语义、Journal和未决写记录。没有真实EA交易测试。
