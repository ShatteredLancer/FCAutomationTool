# 市场任务竞价与多评分实施

2026-11-18：累计实现纳入 [27.0.114](releases/27.0.114.md)。用户后续取消“批量填价”，当前仅保留逐行定价；下方早期检查记录中的批量控件属于历史状态。

用户已批准：一个任务可含多个评分；编辑页购买方式为一口价/竞价/两者，默认原一口价。逐评分表按模式显示竞价上限、一口价上限和挂牌价；只持有隐藏挂牌价且无需填写。最多先展示五档，其余展开，不加内部滚动。整行空白或半填档不执行，至少一档完整；范围外价格保留。买卖独立，不引入利润反推。

## 参考行为及已批准差异

本地 Enhancer 27.0.0.4 readable：33147同一EA bid函数用于竞价与BIN；99611无人报价取startingBid，否则EA下一档；83847支持指定金额或下一档并分别统计bid/won；43303、67717按filter拍卖ID追价、收获；30154每搜索有界串行处理。30501/5152指定评分先得名单，再每轮抽一个defId，并非EA原生评分批量搜索；39887是结果端评分范围过滤。

批准差异：FCAT保留用户既有公共报价及全账号调度；评分档轮转而非随机名单；Both模式BIN符合上限优先，否则可按竞价上限出价，不沿用Enhancer BIN前置校验造成的竞价漏选。既有预算、仅本任务归属、停止恢复及只持有语义保留。参考到的外部批量清理、全TL重挂不扩展授权。

## 完整流程与步骤

1. B1：任务配置、独立竞价价格、评分表/单一价格模式及EA档位；旧配置默认BIN。用户保存/复制/重开/改评分/只持有都必须保留输入，未配置档明确跳过。批量填价折叠且只改勾选档，不自动复制其他评分。
2. B2：评分轮转及买入选择纯规则。BIN使用maxBuy；竞价使用maxBid且不误设maxBuy；Both交替覆盖BIN和bid搜索机会，结果按独立上限决策、拍卖去重、同任务归属，原每次搜索操作上限保持。
3. B3：竞拍账本。出价成功记录leading而非持仓/采购；未知请求仍pending阻止重发，鲜读竞拍确认outbid/lost/won。总成本/本任务/累计预算/数量及未来Transfer容量包含在途，EA余额不再次扣已冻结出价。补价仅算新增资金，中奖才转持仓并记实际采购；停止不再追价但保留核对；预算和未知证据不清理。
4. B4：原生适配及调度。审查真实watchlist读取/实体/竞拍调用方法，恢复读取不交易。原锁、共享请求门控、账号/任务/停止/价格/版本等最终边界保留。赢得实体可入原移卡/挂牌或只持有链路。定时买入结束停止新竞价和追价，已发竞拍结果继续核对。
5. B5：列表/详情显示当前评分及leading/outbid/won/lost，未决交易与正常等结束区分。桌面/窄屏、保存和回读、跨任务公平、任务暂停/重启/刷新恢复生产组合及Chrome场景。最终构建专用安装校验；真实出价、追价、赢得、移卡及挂牌由用户验收。

验收矩阵：旧BIN不变；多评分两侧价格及只持有；无人出价/加档/指定上限/BIN优先及超限跳过；重复拍卖、多任务预算、EA已冻结金额不双扣；落标退款/赢得/回包丢失/401/拒绝/写失败；暂停、定时截止、账号切换、刷新后只读恢复，零自动续跑；EA接口未核实不发送。
