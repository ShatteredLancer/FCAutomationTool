### 2026-10-03 自动出售与定时挂牌计划（仅计划，未接通交易）

#### 参考行为核对

- Enhancer Gallery 的购买链在 `tPt → r8 → xAe`：逐张查价/买入/移动成功后，再按每张卡的出售价格映射进入挂牌；默认 `sellPercent: 0` 不会自动产生出售价格，用户需要明确设置出售规则。其卖价使用已查到的市场参考价乘百分比，再按 EA 价格阶梯取整；`isListPriceAllowed` 会读取 EA price limits，超出范围的卡跳过。买入失败不会生成挂牌项。
- Enhancer 的通用挂牌 `xAe` 使用 `services.Item.list(item, startBid, buyNow, duration)`，逐项显示进度；不可交易、非 Transfer 来源且 Transfer 满、无价格或 price limits 不允许时跳过，单项失败继续。该循环本身没有按 429/473 停整批的分支，不能把 Fodder 的错误处理写成 Enhancer 行为；FCAT 既有熔断与未知回执保护属于需要列明的集成差异，挂牌后精确对账也属于 FCAT 事务要求。
- Fodder GG Gallery 的 `B4` 只负责选中缺卡和购买；批量挂牌是独立的 Bulk List 面板。它支持按市场价百分比、固定价格或 EA 价格阶梯调整，用户可以逐卡覆盖价格，先批量查价再按可配置间隔（2–15 秒）挂牌；已过期卡另有 Bulk Re-list。Fodder 的 `schedulePass` 是 DOM 刷新调度，不是定时出售，不能误读成自动交易调度。
- 本地现有交易层已经有唯一 `services.Item.list()` Adapter、逐项 Listing Transaction、`bulk-relist` 聚合事务、Web Lock/Lease/Journal/429/427 熔断、定时 Job 和公平轮转。Gallery 应调用这些共享层，不复制一套交易实现；旧层当前有单次最多 4 项、来源/FSU 定向校验和其它交易门禁，需在实现前逐项核对 FC27 Gallery 的批准边界。

#### Transfer List Bulk List 来源与 FCAT 复用边界

Enhancer 在 Transfer List 的 Available/Unsold 分区注入同一 Bulk List 面板：参考 `artifacts/fodder-research/enhancer-index-readable.js:69921` 的 `gMt/yMt/SMt/ID` 和 `:69958` 附近的 `wMt/CMt/EMt/TMt`。FSU 同样会在 Transfer List/待分配的 `UTSectionedItemListView.addItems` 添加批量拍卖（`FSU_mod/【FSU】EAFC FUT WEB 增强器-26.09_mod.user.js:3779`、`:4229`），不能仅凭页面位置排除 FSU；它的入口为“批量拍卖球员/Bulk Auction Players”，使用缓存价格、选择时长并逐项等待 2–4 秒。Fodder 另有 `fodder-gg-bulk-list-btn` 和 `fodder-gg-bulk-relist-btn`（`client-current-readable.js:2992`）。本轮没有用户所指按钮的 DOM/截图证据，因此只能确定名称和行为对应关系，不能断言实际页面由哪个插件注入。

建议以 Enhancer Bulk List 作为挂牌面板的单一参考，不混用三套插件默认行为：全选/逐卡勾选、卡片或表格、逐卡改价、Percentage/Fixed/Steps、Start Bid、时长、等待区间和前台逐项结果。`Qh/xAe`（`:65644`）默认 Percentage 100–100%、Steps 0、等待 3–5 秒；百分比在配置范围内逐卡取值后按 EA 阶梯取整，非固定模式 Start Bid 为 Buy Now 前一档，固定模式可另设 Start Bid。`sellPercent=0` 是 Gallery 买后自动挂牌的关闭设置，不是 Bulk List 面板的默认报价。

候选复用方式：Gallery 的“挂牌已购卡”打开同一面板，自动带入本次购买回执确认的真实卡并允许取消勾选；Transfer List 的入口带入当前 Available 或 Unsold 分区。共享 UI/执行器，不要求用户手动把每张已购卡先移到 Transfer，也不依赖 Enhancer/FSU 是否加载。当前 `xAe` 支持非 Transfer 来源，须在 FC27 实测 Club 直接挂牌及收集保留。第三方源码复用保留归属并核对许可证。

报价仍有明确 gap：Enhancer `bMt → q_ → U_.player.fetchPrices` 使用其价格服务/缓存，FCAT 无独立访问该后端的等价保证。公开报价或 EA 查价替代必须标明来源并作为差异评估，不能默默换成买入价百分比或声称完全等价。

#### Relist 分为原价重挂和重新定价

- Enhancer Auto Relist（`:69818` 的 `j8/$v`、`:69830` 的 `rMt/nMt`）提供 1/5/10 分钟，默认 10 分钟；到时读取 Transfer 分组，非空 Unsold 才调用一次 `relistExpiredAuctions()`，沿用原拍卖价格。登录令牌过期会取消定时器；关闭页面不运行，后台标签受浏览器节流影响。它不是重新查价逐卡挂牌。
- Enhancer Unsold 的 Bulk List 复用 Available 的面板，用户可重新设价后逐卡 `list()`；Fodder 的 Bulk Re-list 也是独立打开批量挂牌面板，不等于原生 Re-list All。
- FCAT 建议先接通同一 Bulk List 面板的手动初次挂牌与 Unsold 重新定价，再接自动原价重挂。全 Transfer Unsold 才能使用现有聚合 `bulk-relist`；若范围只限某次 Gallery 购买，必须按精确 item ID 逐卡重挂，不能调用会影响其它卡的全量接口。当前旧交易层的四张上限、有限调度次数和报价上限与参考有差异，实施前逐项记录适用范围，不把“挂牌四张后结束”作为 Bulk List 的完成结果。
- 定时重新定价与定时初次挂牌是独立扩展，不得混入默认 Auto Relist 或悄悄降价。恢复点：完成来源和行为核对、只更新计划；下一步先形成单一参考对照与差异表，再实施 T1/T2。尚未新增交易代码或执行真实交易。

#### 推荐产品流程

1. 优先提供 Gallery“挂牌已购卡”，直接带入已确认买入的实体到 Enhancer 风格 Bulk List 面板；Transfer List 共用该面板。购买默认保留 Club。后续“买入后挂牌”可复用这套价格设置，属于用户明确选择的买后处理，不改变全局交易 Job；不额外添加买入价百分比模式。
2. 购买会话只把**已确认买入、入 Club 且精确匹配 `itemId + definitionId`** 的实体交给挂牌准备；缺货、未知成交、入库未确认、账号/页面变化或重复身份冲突都不自动挂牌。收集确认继续独立记录，不能用“已挂牌”替代 Gallery 收集确认。
3. 挂牌前刷新 Transfer 和 price limits，复核 tradeable、pile、item/definition、Active Squad/锁卡/Evolution/不可交易状态、Transfer 容量及价格指纹。任一未知项停止并保留 Journal；不把预计收入计入预算或净成本。
4. 执行使用已有 Listing Transaction：逐卡前台进度、有限节流、单卡失败继续；429/427、未知回执、Transfer 变化或对账失败停止后续并进入 Recovery。成功必须回读同一 item 为 Active，记录 tradeId、Start Bid、Buy Now、duration。
5. “自动出售”第一阶段只实现买后挂牌；成交由 EA 后续状态观察确认。卖出确认后才写入 `net-cost.js` 的税后收入；未售出、过期和仍在 Transfer 的卡继续作为持有成本。
6. 定时挂牌分两种 Job：
   - `gallery-listing`：仅针对一次购买会话产生、尚未处理的精确 item 集合，按 `once/daily/interval/window` 执行；不允许“扫描整个 Club 后自动出售”。
   - `bulk-relist`：复用现有过期拍卖重挂 Job，范围是全 Transfer 的 Unsold，必须明确展示；只处理有原始 tradeId、Bid/Buy Now 和 expired 状态的卡，Available Items 不算过期拍卖，空列表零 EA mutation。仅 Gallery 批次的重挂使用逐卡路径，不得误接全量接口。
7. 定时任务使用现有 Scheduler 的持久 Job、有限授权、跨标签锁、Lease、Continuation、429 冷却、公平轮转和 F5/重载恢复。定时任务创建后默认 disarmed/paused，必须由用户结构化批准；浏览器关闭或 EA 会话失效时只记录 missed/waiting-session，不能在下次登录盲目重复挂牌。
8. Gallery 已购卡不直接混入 Transfer List 的全量 Bulk List。购买会话先产生精确的 `itemId + definitionId + purchaseReceipt` 投影，用户在 Gallery 的买后处理选择“挂牌”时才把这批卡交给同一 Listing Transaction；Transfer List 的 Bulk List 入口仍可作为后续人工补挂入口。这样可复用 Enhancer/Fodder 的价格体验，又不会把 Club 中其它卡误售。

#### 价格和出售规则

首版建议与参考插件兼容，但明确显示实际公式：

- `market-percent`：以面板明确标注来源的市场参考价为基准，在配置百分比范围内逐卡取值并按 EA 价格阶梯取整；Bulk List 参考默认 100–100%。Gallery 自动挂牌的关闭状态另存，不能把 0% 当成 Bulk List 默认值。
- `fixed`：用户输入 Start Bid/Buy Now，提交前通过 EA price limits 复核。
- `steps`：在市场价上按 EA 价格阶梯上下调整，禁止直接使用不合法的任意数字。
- 预览同时显示挂牌数量、总买入成本、预计 Buy Now、EA 税后预计收入和“预计”净变化；预计收入永远不能抵扣购买预算，只有 EA sold 回执才计入实际收入。

## 三、行为边界

1. 展示、选择和分页以 Enhancer/Fodder 已核验行为为基准，实施前逐项列原行为与本地行为；不要再次自行发明菜单或多层确认。涉及两个插件不同的交互时，优先延续当前已确认的 Enhancer 浏览结构，Fodder 用于补充升档/选卡能力；实质冲突先澄清。
2. 购买继续用户明确指定的 FSU 算法，不改成 Enhancer 的 85%–100%/3 次，也不混入 Fodder 的调价策略。第三方展示参考价和实际 FSU 查价不是同一价格保证，要明确显示预计和成交差额。
3. 已批准的独立数据来源、本地计分、增量调度和 top-100 候选继续有效。FO 人工编辑等涉及参考服务端的能力先核对数据合同；不默默上传账号资料，也不以缺少私有后端为由伪造结果。
4. Enhancer 完整 UI 组件的复制/再发布许可尚未确认，参考行为对照不等于可直接把其 bundle 纳入 MIT 产物；此为既有文档中的明确差异，不能报“完全照搬已完成”。
5. 本次计划不授权 Agent 消费金币、出售球员、领取奖励或提交 SBC；既有读权限可用于数据/页面验收。真实交易由用户主动操作或另行明确授权。
