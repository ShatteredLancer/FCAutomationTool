# Al Hilal：EA 15,320 与 FCAT 15,830 的差异调查

## 已有证据

用户提供 2026-10-31 的 EA 游戏照片、FCAT 集合截图及 `05-01-20-538Z` 诊断。诊断版本为 27.0.78。EA 显示基础 7,550、加成 7,770、总分 15,320，距离 S（15,500）180 分；FCAT 显示基础 7,550、加成 8,280、总分 15,830，并列出相同组合 FUT.GG 分组口径 15,769。差异在加成，净差 510。

诊断保留了该次 15,500 目标的规划汇总（bestScore 15,830），但四条详细 replay 都已被后续 set 142（目标 8,500）覆盖。日志没有 Al Hilal 的逐卡 firstOwned、首任来源或完整 FCAT 计分名单。因此不能把构造输入当成真实账户首任列表，不能认定某张卡被误标，也不能确认历史缓存、手工标记或 EA 未重新计分是哪一个现场原因。

2026-11-02 使用既有代理读取公开 FUT.GG 目录和 set 190 卡池，两次 HTTP 200。公开门槛与截图一致，池 44 卡、需 15 卡。仅匿名公共 GET，没有访问 EA、安装插件、改账号数据或 Regrade。当前公开资料不是 10 月 31 日的原始 EA DTO。

## 可复算的差异分解

从 EA 图片可见评分、版本、国籍和位置重建 15 张卡；公开基础分合计恰好 7,550。按当前 Fodder 分组口径，除首任外计入的九项加成如下；其排序也与游戏图片的十项标签排列一致。

First Owner 按 5–9 张档位计算 150%：

- 首任基础分合计 **4,125**：`floor(4125 × 150%) = 6187`；`7550 + 1583 + 6187 = 15320`，与 EA 图片一致。
- 首任基础分合计 **4,465**：`floor(4465 × 150%) = 6697`；`7550 + 1583 + 6697 = 15830`，与 FCAT 图片一致。
- 两者相差首任基础分 **340**，加成差 **510**。

固定这 15 张公开卡，枚举全部 32,768 种首任布尔组合：能得到 15,320 的输入有 43 种（6/8 张首任，均为首任基础分 4,125）；能得到 15,830 的有 68 种（7/9 张首任，均为 4,465）。这说明首任输入差异能完整解释数字，也明确说明仅凭总分无法反推哪张卡被误标。

最初仅凭总分，82 Koulibaly 和 82 Theo Hernández 都是 340 基础分的数学候选。随后用户补充 FCAT 首任筛选截图（`捕获1.PNG`，1–7/7），确认名单包括 Theo、不包括 Koulibaly。此次 FCAT 七张为：Neves 85（2100）、Milinković-Savić 84（830）、Martinelli 82 TOTW（425）、Watkins 83（410）、Theo 82（340）、Salem 80（180）、Martinelli 80（180），合计 4465。移除 Theo 的首任加成可精确闭合 EA 差额，但没有 EA 逐卡首任明细，不能据此宣称 Theo 必被误标。fixture 保留 Koulibaly 分支仅作同分数学对照，不再把它列为截图中的首任卡。

FUT.GG 对照的另外 **61 分**来自 Multiples：Fodder 口径同时计入两组重复球员，`floor((3455 + 605) × 10%) = 406`；FUT.GG 对照仅取一组，`floor(3455 × 10%) = 345`，于是 `15830 - 61 = 15769`。它能解释 FCAT 页面上的“规则差异”，不能解释 FCAT 与 EA 的 510 分差异，不能用切换分组口径修复本次问题。

## 代码核对与验证

现有首任输入来自当前 Club `owners=1`、账号内历史 `collectedOwners=1`、或显式本地 FO 历史标记；概念卡 owners 不直接作为首任证据。历史 owner 数按最小值合并，保留“曾首任拥有”证据；本地手工标记优先。这些路径需要针对实际争议卡检查，不能只凭截图就删除所有历史首任或改变规则。

本轮没有修改生产计分器、首任政策或缓存，也没有重新构建/安装脚本。增加公开元数据 fixture `tests/fixtures/fc27-gallery-al-hilal-score.json` 和针对性回归，明确标记 FO 情景是构造输入。

补充核对本地 Enhancer 公开 bundle `artifacts/fodder-research/enhancer-index-readable.js`：28840 行的 `getOwnerCount` 与 FCAT `ownerCount` 条件相同；28900 行 `GBe/fy` 按精确版本保留最小 owners，并按账号持久化；28914 行 `bge` 过滤 player/isCollected；28920 行 `iFe` 在 factory 创建时保留 gradingScore/isCollected 并观察。因而不能将“离开 Club 仍保留历史首任”认定为 FCAT 偏离参考实现。截图 Theo 的 Club 问号表示当前 Club 状态未知，不等于从未首任拥有；无“清除历史 FO”按钮支持自动观测而非手工标记的调查方向，但仍缺该版本的底层缓存证据。卡面其他插件的黄色 YES 不作为独立 EA 首任证据。
