# FC27 存储体积维护（27.0.56）

## 已确认范围与实施计划

用户授权：优化 FCAT 历史记录和缓存，保留锁卡、设置、待核对交易；测试后提交并推送 main。

1. 核对当前 main、原始备份和实际存储分布；不改用户原始备份或浏览器配置。
2. 在原有 Journal 的 get/set 边界无损压缩完整对象，兼容旧版明文。
3. 启动时迁移既有大记录；交易记录迁移必须取得与交易相同的全局 Web Lock，忙/不支持时延后。
4. 给可重建的评分/映射检查点加 UTF-8 容量上限；保留画廊曾拥有/首任历史。
5. 覆盖损坏、写失败、刷新、跨账号及锁竞争，再执行完整验证、离线 Chrome 验证和上游复查。

不改变预算、单卡上限、选材、锁卡/阵容保护、购买/贡献/恢复规则；不发出 EA 请求或交易。

## 证据与原因

备份中 FCAT 共 10,488 个 GM 值，约 58.55 MiB。其中采购历史快照约 27.44 MiB，
活跃采购记录约 4.67 MiB；评分和映射检查点也重复保存较长的规范化输入。
Chrome 曾报扩展消息超过 64 MiB，但未捕获那条实际消息，所以备份大小不等于精确的传输大小。

失败回归先于修复：`fc27-storage-size.test.js` 三项分别复现完整待核对记录原样占 605,412 字节、
评分按字符计数导致 2,400,879 字节、映射无体积约束达到 9,006,484 字节。

## 当前实现与边界

- Streamlined contribution、purchase 的活跃记录、history、retired 全量 gzip；不是摘要或删字段。
  无论记录多久、是否 pending/unknown，均不按年龄或容量删除；保留凭证、预算、保留卡及原始状态。
- 解压异常必须让 Journal 读取失败，绝不当作“没有待核对交易”。解压最多 32 MiB，校验声明长度和 gzip 完整性。
  不支持压缩时保持原写法；已有压缩记录读不出时继续保留，不覆盖为空。
- 启动迁移只认 FC27 两种 Streamlined 键和两种派生缓存键，检查账号上下文；
  与交易共用 `fca-fc27-traditional-sbc-v1`，锁内重新读取、写前比较、写后复读。
  启动自动核对等待本轮维护结束，避免迁移持锁吃掉每账号的一次核对机会。
- Gallery score/mapping：每键最多 2 MiB UTF-8，淘汰可重算的旧行；内存保留最多 4 个 scope。
  持久化派生缓存最多 8 键/8 MiB（含 GM 类型标签/JSON 转义估算），写入时优先保留刚写的键。
  不清 collection、first-owner、锁卡、设置、购买/贡献记录。
- 公开 Gallery pool/catalog 的 gzip 阈值从 128 KiB 降至 32 KiB；格式和业务内容不变。
- 启动报告 `__FCAT_STORAGE_MAINTENANCE__` 仅包含计数/字节，不暴露账号、球员或交易标识。

## 场景矩阵与验收状态

| 前置/动作 | 预期与副作用 | 验证 |
| --- | --- | --- |
| 原始明文大记录，刷新/再次运行迁移 | 逐字段等价；第二次不重复压缩；EA 请求 0 | 单元+私有备份副本回放 |
| buy-pending/move-pending/unknown、retired，换账号后读取 | 状态、隔离、保留实体及完整证据不变 | 单元 |
| 锁忙/锁不支持、迁移前另一事务写入新回执 | 延后/锁内读最新版；不覆盖新状态 | 单元 |
| gzip 损坏、声明长度错误、读写失败 | 保留记录并失败；不得视为空记录后再次提交 | 单元 |
| Unicode 大评分/多映射/多账号缓存 | UTF-8 和总量限制；仅重算派生缓存 | 单元 |
| Chrome 原生 CompressionStream/Web Locks、Journal 刷新恢复 | 完整 roundtrip；原生锁忙延后、损坏拒绝；无 EA 调用 | 离线 Chrome 通过 |
| 升级后真实油猴首次启动及后续运行 | 启动报告完成、原锁卡/设置/待核对仍在 | 待用户升级后实机验收；离线检查不代替此项 |

原始 ZIP 与解出的数据只在私有临时目录进行副本回放，不进入仓库。
所有交易证据都保留，因此这不是对无限增长交易存储的硬性总量承诺，也不能在油猴已经拒绝注入时自行运行迁移。
遇到这种情况保留备份并先恢复注入，不卸载/清空脚本数据。

## 本次验证结果

- `npm run verify`（4 workers）：423 文件通过，5,069 项通过、39 项跳过；语法、lint、配置、架构、FSU 边界、构建和根目录/dist 对齐均通过。
- 全套 `node scripts/browser-inspection/run.mjs --self-test` 通过。新增 Chrome 用原生 gzip 和 Web Locks 测试完整 Journal、锁忙延后/释放后迁移、unknown 阻止重复操作、损坏读取失败；EA 请求 0。
- 私有备份副本：61,392,707 → 17,443,484 字节（71.59%）。59 个变更值完整还原一致，10,429 个值字节不变，10,488 个键全部保留；交易记录未删除。原始 ZIP SHA256 未变。
- 首轮完整测试暴露 native gzip I/O 不受 fake timer 驱动，原本只运行一次假时钟的测试需要持续等待真实 I/O；已修测试调度，保留真实压缩和原超时/业务断言，不禁用压缩或延长截止时间。
- 原有 Chrome 关页锁释放 smoke 的一次性读取有竞争；改为在原 10 秒内轮询只读锁获取，仍检查 pending 状态且不发送写入。生产交易锁实现未变。
- 提交前复查：所有 Journal 消费者继续经原工厂解码；预算、报价、物品验证、恢复判定及交易副作用入口无改动。新日志若有批量上架待核对，属于保留的独立交易证据，不按缓存处理。

实机剩余项：在油猴原位更新 27.0.56 并刷新其他 EA 标签后，核对启动维护完成、原设置/锁卡及待核对记录仍在。当前离线通过不表示已经安装更新。
