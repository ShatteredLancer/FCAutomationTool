# Gallery 联赛规划的查价生命周期与宽池搜索（27.0.77）

## 现场证据与边界

- 用户27.0.76诊断：一轮grade-plan在25,242ms后以`FC27_GALLERY_PLAN_QUOTES_CHANGED`取消，保留完整脱敏输入；另一轮FUTBIN/FUT.GG quote-batch分别等待387,445/247,860ms后失败，之后记录页面离开。网络失败与页面离开是不同事实，不能把后者直接说成自动刷新。
- 冻结输入为30个计分位、389张目录卡、80张已收集、295张有价、21条计分规则；目标B为725,000。旧代码在离线固定报价下可走完，但只回报383,392的最佳候选，没有证明无解。
- 原规划查价默认顺次等双源，虽然估价只依赖所选主源；长轮次可读到仅剩几十秒的缓存。宽池热启动先耗在低价档，且未达目标的搜索bestState没有进入最终复核/显示。
- 日志中的报价不是现在可成交的报价；不使用真实账号交易验证，不把本次规划修复宣称为B档必然可达。

## 修改

1. 指定档位/各档费用/联合规划与重算使用`gallery-plan`只读用途，只请求用户选定的报价主源；普通卡片双源比较不改，不自动切源、重置设置或调整限价。
2. 本轮所有规划查价页及一次临期更新共用90秒截止。沿用公共服务的队列、pending、并发、退避及截止后不释放未完请求的约束。没有可用报价直接显示“来源未返回报价/90秒超时”，不继续跑无报价的大搜索。浏览器冻结可能推迟回调，恢复后的截止检查仍会停止后续读取；不是后台绝对墙钟保证。
3. 距到期少于TTL三分之一（最多60秒）的已知主源报价，仅该版本强制更新一次；仍使用同一来源/政策与截止，失败不退回旧价。原fetchedAt/expiresAt不延期，长请求后过期卡剔除，源/账号/材料变化仍停止。计算过程中再次到期仍停止；购买前原独立核价/审批不改。
4. 已有卡及缺卡都达到两倍计分位的宽池，先给完整已报价池一次原scorer选队机会，再进入低价档与原成本搜索；热启动仍共用16k步骤及原总评估预算，不提高节点上限，也不把“高分”代替成本目标。
5. 未达档位也保留bestState，使用原scorer校验确切完整阵容并显示保守最佳分数/缺口。未达目标不生成购买入口；已达标方案仍走原完整owned+selected复核。内部仅需低分时复用已有fastTotals，最终分数仍完整验证。
