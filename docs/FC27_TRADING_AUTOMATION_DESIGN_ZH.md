日期：2026-11-14。状态：按用户要求留档提交，准备分步实施；生产基线27.0.108，本次不升版、不修改生产交易逻辑，不执行真实买卖。

## 当前有效布局：单页任务管理（第二版）

用户否定第一版分散的Tab和复杂设置，指定FCAT只保留一个“市场交易”Tab，在主页面新建交易任务、选择三种模板，保存后在任务列表启动、暂停、停止、删除。任务参数放任务编辑页，其余设置放交易主页面。以下覆盖第一版的四个交易子Tab布局；旧版仅留 artifacts/trading-mock-v1.html 作对照，不再作为实施目标。

- FCAT 顶层：“市场”与“交易观察”入口合为“市场交易”，其他Gallery/库存/SBC等入口保留。已有交易观察、持仓、历史Journal和情报数据需保留并迁移展示，合并导航不代表删除旧数据或直接让旧任务运行。
- 主页面：搜索额度与简短资金汇总、任务列表、`新建交易任务`、`暂停全部`。列表列出名称/模板/规则摘要、状态、买挂售数量、持仓成本、已实现利润。主操作为启动/继续/暂停、编辑；停止、复制、删除放每行更多菜单。任务名称打开详情，持仓/挂单/日志不另占Tab。
- 公共交易设置：在主页面折叠区设置报价源、实际账号平台、所有任务共用的资金留存/持仓上限、搜索频率/休息、小时与日限额、错误停止。账号额度由所有任务共享，不能每个任务分别获得1000/5000。全局设置变更后暂停活动与排队任务，重新启动才按新设置运行。
- 任务编辑：任务名、固定名单/条件选卡/持仓出售三选一、对应选材、买入上限/卖出规则/数量；预算、累计采购上限、运行期限、重挂折叠为高级设置。保存只存任务，不启动。编辑活动任务前提示暂停；已有交易记录不因改规则而改写，旧挂单的价格只在合法到期后的显式规则下应用。
- 当前调度设计：一个账号一个EA执行队列，多个已启动任务按短轮次轮转；一次搜索及其已发交易处理到明确确认点后让出机会，长期任务不独占队列。搜索等待与休息是全账号门控，不能靠切任务绕过。`暂停全部`不提升任何队列任务。mock目前仅演示单个活动任务与排队/暂停提升，尚未模拟短轮次调度；生产以文末调度及分步实施计划为准。

### 任务生命周期

| 操作 | 后续执行 | 资金/持仓/回执 |
|---|---|---|
| 保存 | 待启动，不发请求 | 保存规则 |
| 启动 | 重新核价与资格后运行；已有运行任务则排队 | 原硬上限/共享资金边界仍有效 |
| 暂停 | 停止新请求；在途请求仍核对；可继续 | 保留已用时、累计采购、持仓、挂单 |
| 继续 | 先核对再续原任务，不重新清零额度 | 原成交不重买、原挂单不重挂 |
| 停止 | 结束本轮，取消后续买入/自动重挂 | 不撤市场挂单、不出售持仓；再次运行复制新任务 |
| 删除无交易任务 | 从列表删除 | 仅严格无在途/无交易证据时真正删除 |
| 删除有交易任务 | 停止并归档，从默认列表隐藏 | 旧持仓仍占全局成本，完整账本留存，归档筛选可查看 |
| 未知回执 | 进入待核对；不能用停止/删除清除不确定性 | 先完成只读恢复，不伪造已完成或未成交 |

停止/归档后剩余卡可显式导入新的“持仓出售”任务。生产需要按精确实体转交管理权，防止旧任务与新任务同时拥有同一张卡；复制任务只复制规则，不能复制交易审批/回执，也不能隐式获得重复持仓的出售授权。

## 三种模板

共用买卖定价、资金、节奏、错误处理和持仓账本；模板仅决定目标如何产生。

2026-11-14 用户追加：条件选卡默认仅展示最低评分、最高评分、每种卡持仓上限；持仓上限默认留空（不限），存储语义为null，不能误当0或Infinity。品质、联赛、位置、国籍、俱乐部、排除项合并在“更多筛选”，新任务默认不附加这些条件；已选条件在折叠标题摘要展示，避免隐形过滤。有限上限可保存并回读，清空恢复不限。不限只解除单版本数量限制，不解除本任务/账号资金、累计采购、时间及EA槽位限制；不再展示“买齐0张/0金币”等错误汇总。

1. 固定名单：输入球员名字→显示每个精确版本（EA 卡面/评分/版本/平台报价）→添加具体 definitionId。每行显示参考价、可编辑买入上限、最大同时持仓、预估税后利润及移除按钮。默认继承公共规则，逐卡覆盖需明确标识；不得仅凭名字把普通金与特殊版本互换。已持有及在途副本占数量。示例：Raya 普通金最多 3 张，并不限制一次任务只能买 1 张；卖出后是否补仓由持续运行边界约束。
2. 条件选卡：评分范围、品质/稀有度、联赛、国家、俱乐部、位置、排除版本；身份条件 AND，同一多选组 OR。买入价格和每版本数量也作用于最终候选；卖出定价不参与买入筛选。评分等不能直接表达的 EA 搜索条件先在公开目录/缓存筛出精确版本；未知字段不能当匹配，缺价不能当免费。公开 cheapest 只作有限候选来源，不代表全市场覆盖。保存条件和统一排除名单；每次新启动按最新可用目录匹配，当轮固定候选，继续运行不重新扩展。默认只显示条件摘要，不为总数扫描目录；预览按需展开，每页最多5张并支持名字搜索，只显示已预览数量和是否还有更多，不声称全市场覆盖。
3. 持仓出售：按 Transfer/Unassigned/Club 来源查看可售实体，逐张勾选。同版本多张不能合并身份；活跃挂单、不可交易、锁卡/主阵容保护不能导入。成本未知显示未知，仅使用独立固定/参考定价，不计算利润或用虚构成本走买入价规则。只管理明确导入或本策略购买的实体。

持续策略需要新增版本化的策略授权及逐实体 Journal，不能直接修改旧计划 schema 的 quantity 来支持循环。记录每笔实际成本、在途额度、持仓成本、累计采购、挂牌回执与售出净收入。保留旧任务恢复与跨模块互斥，不清除未知交易以启动下一批。

## FCAT 限制提案与差异

1. 全局顶部显示本机已观测搜索滚动1h/24h、已设阈值、冷却/可继续时间。截图1000/5000可作预填参考，明确非官方额度。买入、挂牌、移卡另记次数与冷却，不伪造未证实的EA买卖额度。
2. 请求门控应跨 FCAT Trading/Gallery/SBC，翻页/重查按真正发起的搜索计数，纯公共报价单独计。缓存命中不算网络搜索；超时已发出的请求计数，零发送不计。同一真实请求只计一次。**这与所查 Enhancer 仅成功响应才加 usage point 不同，是待确认的FCAT提案**；可以另外展示成功次数，但不得将失败请求当没有服务器负载。
3. 持久化按账号/平台分桶，跨标签锁内预留避免两个标签同时越限；刷新不归零。后台节流后不能积累一堆“补发”任务。已观测其他插件/手动请求也计入，但无法声称掌握其他浏览器全部请求；未知覆盖明确展示。其他插件运行检测不可靠时需用户单独停止其自动交易。
4. 达到搜索阈值阻止新搜索。对超额或降低阈值，恢复时间按足够数量事件退出窗口计算，不直接将最早事件过期当可恢复。挂牌/回执读取按各自门控；遇整体认证/服务限流则全任务暂停。
5. 默认勾选512/521、429和市场不可访问，容量不足暂停买入/移卡，478明确竞争失败可跳过单条；验证码/401与未知回执沿现有保护。所选可配置错误采用Enhancer的每码累计语义。**默认选中哪些码、额度触发自动停止是FCAT提案，不是已证明Enhancer原样行为**。用户审阅后才能实施；不能取消现有未知回执/认证保护以模拟“无限重试”。
6. 不把Fodder的SBC退避或401自动重试移到付费市场动作。搜索无货、明确竞购失败与买入/移卡/挂牌回执未知分开。后者仅核对。

## 全账号调度与任务协调

任务保存选卡、独立买卖定价及作用范围，不各自建立请求循环。账号/平台统一执行器承担EA市场搜索、买入、移卡、挂牌及回执核对；公共报价走独立有限并发队列，不能因此增加EA请求并发。

1. 多个已启动任务短轮次公平轮转：一次搜索及关联的已发操作到明确确认点后让出机会。已发交易核对优先；到期挂牌/重挂每轮有界，避免无限占用。等待卖价条件、挂牌到期或本任务条件的任务不持有执行槽。买入后按选定卖出规则处理，不为了轮转强制卖出。
2. 公共搜索间隔、随机休息及滚动1h/24h额度跨任务累计。A搜索后公共冷却未结束，B也不能搜索；不会用任务切换、暂停继续、刷新或后台计时积压绕过节奏。实时状态显示正在处理的任务/阶段、排队原因、公共下次可搜索时间。
3. 发出买入前在账号锁内预留预算与在途金额；多个任务不能花同一份余额。同一挂单不能被重复购买；每张实体只属于一个管理任务，移卡和挂牌绑定精确实体/交易ID。普通版本和特殊版本、多个同版本副本分别处理。
4. 用户暂停/停止只取消未发送动作；在途先核对。未知成交、移卡、挂牌结果保留Journal及占用，不通过重试、删任务或切任务消除。认证、验证码、整体限流暂停全账号市场队列；正常无货/明确竞购失败按阶段及任务策略处理。
5. 与Gallery、Puzzle、Streamlined已有采购/挂牌入口共享账号协调，不复制一套绕开公共门控的买家。接入时保留各模块原限价、报价TTL、保护和恢复合同，公共等待不能默默延长旧报价有效期；超期按原流程重核或停止。
6. 同账号多个FCAT页面只允许一个执行所有者，跨标签锁/revision防重复发送；刷新后先恢复核对，不能自动重启旧任务。账号变化撤销旧账号执行权，分桶保留旧记录。可观测其他插件/手动请求计入但不能声称掌握其他浏览器或设备的请求。

来源差异：7–15秒、10–15次后休息5–8秒、每搜索最多买1张来自所查Enhancer Trader。1000/5000是其用量显示参考值，不是已证EA官方限额或Trader自动停止合同；FCAT的已发请求计数、跨模块门控和触阈值停止为本设计的差异，不能声称原样复现。原版60–120分钟停止未沿用，用户要求运行时长默认不限。每次搜索允许多买时，实施前必须一并核对原版delayAfterBidFor和UI最低等待，不能只复制数量参数。
