## 实施计划与边界

1. 先写周转现金流失败回归：累计采购超过初始本金但分批可行；单卡超本金；多批税损侵蚀；拆批/顺序与去重；未知/过期报价；回售价估计与实际成交分离。
2. 增加只读总路线模型，复用原单合集计分/档位规划与共享精确版本语义；自动扫描全目录目标，不要求用户逐个添加联合目标。显示覆盖范围、已达档、未知/缺价/候选截断和有界搜索，不把部分分析说成全局最优。
3. 全局默认按低预计净损耗展示候选并显示收益/本金，支持可周转金币输入；本金额仅用于现金流可行性，不作为累计采购额上限。默认回售价场景必须公开，不能把假定卖价当真实价格或已实现收入。
4. 总览新增“整体方案”入口与进度/停止/清楚的资金卡片、俱乐部路线表、共用卡清单；“进入俱乐部”只跳转/带目标，不买、不卖、不领取。手动联合规划与原俱乐部操作保留。
5. 匿名 JSON 分析导出：目录/卡池版本与时间、精确版本公共属性、已收集/持有/首任/证据来源及时间、评分区间、档位/奖励、价格平台/新鲜度、完整性。领取状态未核实保持unknown；去重公共版本，不在GM存第二份大快照。
6. 加正常/未知/失败/取消/账号切换/目录漂移/刷新/重复操作/跨合集共用的Node及离线Chrome贯通验收；完整verify、主线差异与产物复查后按用户既有约定提交推送main（若本轮后来另有不推送指示则遵守）。真实账号只读检查，买卖/填阵不用于测试。

## 资金计算合同

每一步以买前余额核对采购价，收集确认后才允许计划进入回售阶段；预测现金流与实际到账分开。
所需本金按整条批次路径的最大前置缺口计算，累计采购额仅是统计项。预计净损耗为采购价减预计税后回收，含明确的回售价假设；未知价格不补0。
不能用“单卡都没超本金”代替整条现金流验证；多次税损也会让后续卡变得买不起。也不能因先做便宜任务亏了本金而误判高价卡原本不可做，需要在路线顺序中前瞻核对。
