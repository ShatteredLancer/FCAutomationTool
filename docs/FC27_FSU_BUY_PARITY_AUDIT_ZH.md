# FSU 与 FCAT 批量购买行为差异核查

2026-09-28。用户要求完整复现 FSU 行为，不仅是接口顺序相同；不依赖 FSU 加载。下表是修复前的源码核查结果，覆盖此前“已经对齐”的错误结论；最新实施结果见文末，不将原问题清单误作修复后的状态。

## 实际购买证据

`artifacts/fc27-browser/puzzle-stability-live.json` 的 21:01–21:02 记录与用户截图一致：当前 21/48 已购买 **5 张**，逐张为 550、450、600、350、200，共 2150；5 项为 club，applied=5、phase=saved、pending=false，页面对应五张真实卡，剩余五张概念卡。第六项保留 200 报价但状态 waiting，尚未成交。不是固定四/五张数量上限触发。

页面显示 `FC27_BUY_AUTH_REQUIRED` 对应提示，但没有保留这次买断完整数值 error.code/status。原浏览器控制进程在中断后已不在；不能事后伪造具体 401/403 或确认“确实掉线”。监视器原先仅捕获 sbs/club/purchased 路径，未完整记录 transfermarket/trade，也未保留每轮搜索起价，不能声称已经证明当时所有 200 挂牌仍可买。

## 逐项差异

FSU 基准：`FSU_mod/【FSU】EAFC FUT WEB 增强器-26.09_mod.user.js`，`buyConceptPlayer`（约 10327）、`readAuctionPrices`（10555）、`futbinId.getId/getPrice/setPrice`（17501）和原生侧栏入口（16679）。本地：`src/adapters/ea/fc27-puzzle-buy.js`、`src/fc27/fsu-auction-search.js`、`src/fc27/puzzle-buy-session.js`、`src/adapters/ea/fc27-purchase-squad.js`、`src/adapters/browser/fc27-puzzle-buy-button.js`、Acceptance session。

| 环节 | FSU 源码行为 | 当前 FCAT 差异/影响 |
| --- | --- | --- |
| 参考价来源 | 按 FUTBIN ID 取价，未知 ID 按赛季/平台/国家/联赛/球队/评分/位置查询，取 `LCPrice` 等价格字段 | 用 EA `_marketAverage` 充当 observedBuyNow，既不是相同来源，也没有按原链刷新 |
| 缺少参考价 | 经过原价格查询及原异常路径 | 无有效 `_marketAverage` 时直接以剩余金币/单卡上限作为市场查询起点，可能远高于 200；属于实质偏离 |
| 查询模型 | 通过 `UTBucketedItemSearchViewModel` 设置 MARKET、默认条件，初始和调价后调用 updateSearchCriteria | 直接传 DTO，省掉模型处理；最终参数是否完全等价尚无差分证据 |
| 查询次数 | 读取用户 `queries_number`，缺省 5 | 实际调用固定默认 5，没有等价设置 |
| 调价基础 | 从参考价按 EA 档位涨降，查询价不重复 | 涨降外形相同，但起价不同；价格上限/低于 150 的退出和 tick 方法缺失时的 fallback 是新增分支 |
| 中途查价失败 | 提示并结束本卡查价，返回此前累计挂牌 | 抛出异常，之前累计挂牌也不返回，外层结束整批 |
| 挂牌累计与同价选择 | 数组 concat，降序排列后选末项 | 按 tradeId Map 去重/覆盖后升序选首项；同价选单次序及重复挂牌引用处理不同 |
| 购买候选过滤 | 精确查询后选最低价，再检查余额和到期 | 先额外检查可交易、concept、loan、Evo、cosmetic、academy、评分/稀有度/国籍/联赛/球队/位置/groups 等，再选最低价；可跳过原本更便宜的挂牌或误报无挂牌 |
| 最低挂牌已到期 | 本卡标失败，继续下一球员 | 先过滤过期挂牌，可选另一张更贵的有效挂牌；同一输入结果不同 |
| 查询/逐卡节奏 | 查价轮间随机 0.2–0.5 秒，逐球员结束随机 0.5–1 秒；入口延迟 500ms | 原生操作统一最小 800ms，bid 与 move 间也延迟；无原逐卡等待方式，改变候选等待时间 |
| 页面事件 | 查价成功发送 Transfer Market Results 事件，买断前发送 Item Detail View 事件 | 未发送对应 PIN 事件。差异存在，是否影响这次拒绝没有证据，不能直接归因 |
| 买断被拒 | `data.error.code === UtasErrorCode.PERMISSION_DENIED` 提示“被其他用户购买”，本卡失败后继续下一卡 | 不读取数值业务 error.code，401/403 统称 AUTH_REQUIRED 并停止；其它一般拒绝也停止，仅明确 404/409/过期分支继续 |
| 入 Club 失败 | 记录本卡失败，resolve 后继续下一卡 | 停整批、保留 move-pending；未知成交保护与明确失败混在同一停止路径，不是同等语义 |
| 容量和金币 | 开始检查待分配区，逐卡 canBuy；买不起该卡时继续其它卡 | 每张查价前检查容量，新增整批预算和单卡上限；余额/预算失败会结束批次。用户已要求可配置单卡上限，不应将其解释为查询起价 |
| 购前读取 | 从页面 getPlayers 收集 concept，然后查价/买入 | 先精确 Club 查询与服务器 squad 回读；已有唯一同版本 Club 卡直接复用，歧义阻断。请求数及行为都不同 |
| 阵容范围 | 遍历 getPlayers 返回的概念槽 | 只投影前 11 槽，布局拒绝工作区/替补有实体；自定义砖也会阻断，范围比原按钮窄 |
| 保存前置与写后动作 | 购买循环无额外 squad GET/PUT，依赖原生 move/概念替换链 | 要求当前页面/服务器一致；结束重新读 squad，必要时 PUT 和回读，不一致时可阻断。不能把新增网络写入仅称为日志 |
| 再次点击/中断 | 新点击重新读取当前页面概念卡，原循环不持久保存交易 Journal | 可能优先复用未决旧 base/applied，受账号锁、其它 SBC 未决事务和方法指纹检查约束；有额外阻断条件 |
| UI 与反馈 | 需求栏顶部 mini 按钮、原 loader/逐卡提示、失败卡片标记、成功/失败/花费总结；手机有退出详情动作 | 按钮实际在操作区、额外购买设置/停止按钮、文字汇总，缺逐卡失败标记及相同手机动作；不能称 UI 完全一致 |
| 诊断保真 | 买断分支实际检查业务 error.code | 本地持久化只保留归并停止码，缺阶段、数值 HTTP/业务码、逐轮价格和候选排除原因，阻碍这次归因 |

已一致的基本部分：精确 definition 查询、清市场缓存、逐张串行、用当前 Buy Now 调用 `Item.bid`、成功后 `Item.move(CLUB)`、不提交 SBC。上述一致不足以证明整条购买行为相同。

## 与本次价格和停止的关系

价格缺陷已由源码确认：参考价来源被换掉，缺价时又用预算起搜；“所查几页最低价”不等于从 200 附近开始寻找的结果。未保留每轮实际 maxBuy，不能断言五张高价全部由同一分支产生，也不能仅凭卡面 200 证明当时有可成交 200 挂牌。

停止缺陷已由源码确认：同一 HTTP 状态可能对应具体买断业务拒绝；FSU 明确识别 PERMISSION_DENIED，而本地合并为登录/权限故障。当前第六项 waiting 且保留报价与明确买断拒绝路径相符，但具体业务错误码已丢失，不能宣称已实证“被抢走”或“登录过期”。

现有测试主要给定理想报价和归一化错误；未把原版价格获取、真实 HTTP＋业务 error.code、混合高低价满页、已失效最低价、搜索中途失败与全链请求轨迹作为差分基准。因此大量回归通过证明的是自写合同，没有证明与 FSU 等价。
