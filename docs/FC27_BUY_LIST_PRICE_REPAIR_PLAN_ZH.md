## 1. 为什么先停下来

用户要求先明确需求、工作量和验收，再修改。此前的补丁集中修正局部表现，缺少从报价、方案、用户批准到实际交易的完整价格合同，也没有用同一输入逐项证明与参考插件一致。

三个必须分别验证的层次：

1. 价格数据正确：赛季、平台、精确卡版本、来源、时间、有效性。
2. 业务计算正确：估价、允许溢价、实际购买上限；挂牌模式、档位、起拍价与一口价。
3. 执行和显示一致：用户看到的金额与请求金额一致，失败/重试不能扩大价格或重复成交。

当前事实不是“EA 有一个可以替代 FUT.GG 的权威市场参考价”。EA 搜索返回的是当次可见挂牌；一页最低价不能证明全市场最低价。FUT.GG/FUTBIN 也可能不同步，不能假定两者永远相等。此前诊断汇总为方案 10,600、12 张实际支出 13,850，相差 3,250（约 30.7%）；缺少逐卡三源报价和搜索序列，尚不能归因到某一张卡或某次请求。

## 4. 购买：明确的价格合同

对每个精确版本保存两份报价，字段至少包括来源、赛季、平台、definitionId、金额、抓取时间、来源更新时间（如果服务提供）、有效期和失败类别。抓取时间不能伪称源站行情更新时间。

设所选有效参考价为 P，固定溢价为 A，百分比溢价为 R：

- 方案估价 = P，整套估价是所有待购版本的 P 之和；已拥有卡不重复计费。
- 固定模式单卡上限 = P + A。
- 百分比模式单卡上限 = floor(P × (1 + R / 100))。
- 有效上限还受用户显式单卡限制、剩余总预算、余额和 EA 价格范围约束；不把估价总和静默当成用户总预算。
- EA 搜索参数如要求价格档位，只能落到不超过上限的合法档位；不得向上取整突破用户设置。
- 实际买价是所选挂牌的买断价，不是参考价；只有它不超过有效上限时才允许发起一次买断。
- 同一批内重试不能重新放大上限；购买请求发出前再次复核精确版本、金额和当前授权。

金额示例（假设该区间为 50 金币档位）：

| FUT.GG / FUTBIN | 来源与溢价设置 | 方案估价 | 原始上限 | 合法搜索上限 |
| --- | --- | --- | --- | --- |
| 200 / 250 | FUT.GG + 0 | 200 | 200 | 200 |
| 200 / 250 | FUT.GG + 100 | 200 | 300 | 300 |
| 200 / 250 | FUTBIN + 10% | 250 | 275 | 250 |
| 未知 / 250 | FUT.GG + 0 | 未知 | 无 | 不买，不使用 EA 500 兜底 |

页面需要区分“预计花费”“最多允许花费”“实际已支出”，不能只用一个“价格”标签。明细显示两源报价、采用来源、有效购买上限、实际成交价及失败原因。方案金额不能作为实际市场必然可成交的承诺。

### 4.1 获取报价的时机与性能

- 先核实两个服务的实际响应、精确版本映射、平台价格、时间字段及支持的批量方式；不能因为接口路径叫 FUTBIN 就假定数据完全正确。
- 优先已有有效缓存、请求合并和服务明确支持的批量接口。禁止假定未验证的批量参数可用。
- Gallery 不能每次打开分类/切 Tab 都逐卡查询 FUTBIN；在规划所需时按候选范围加载，跨集合去重，显示 `已读取 / 待读取`，支持取消。
- 不只给已经选中的昂贵方案补报价就宣称“按双源规划”；参与成本比较的候选必须使用同一策略。范围被截断或报价不完整必须说明。
- Puzzle 原生需求和目录查询保留；只替换行情读取路径，不修改求解器、材料保护或概念卡保存。
- 短期失败退避、缓存过期、平台切换和账号切换分别处理。报价网络失败不得误报 EA 登录失效。

### 4.2 尝试次数、失败与重试

“每卡购买尝试 N 次”指最多 N 轮“搜索 → 找到合规挂牌则买断”，包含第一次；一轮内部沿用已核对的 FSU 查价次数和等待逻辑，但不得突破新批准的价格上限。不得出现内外重试相乘却不显示实际请求量的情况。

| 结果 | 本批处理 | 用户再次操作 |
| --- | --- | --- |
| 上限内无挂牌 | 次数内可重新搜索；耗尽后标记失败，继续其它卡 | “重试失败卡”，仅包含尚未成交项 |
| 挂牌已售/已过期，EA 明确未成交 | 原上限内重新搜索，不能复用失效单 | 耗尽后可主动重试 |
| 所选公开参考价缺失、设置无效、余额不足 | 显示具体原因，不空转同样请求 | 修复来源/设置/余额后重新尝试 |
| 明确拒绝但原因不明，或返回限流/认证信号 | 按参考实现与实际回执分类；不擅自扩大自动重试 | 明确显示停止/跳过及恢复条件；仅 HTTP 状态不能证明扣款结果 |
| 买断回执丢失/不明 | 暂停后续交易，保留 Journal | 核对原回执；确认未买前不能重买 |
| 已买入但入库/替换未确认 | 保留购买成功事实，恢复入库/替换 | 不能当作“失败卡”再买一张 |
| 已成功 | 保留实际价格与精确实体回执 | 重试、换页、刷新都不能重复购买 |
| 用户停止或换账号/改阵 | 停止发起新交易，结清已发请求的回执 | 已成功/未处理/待核对分别恢复 |

购买页一次显示全部卡和状态，当前卡显示第 k/N 轮；结束后保留清单。普通失败提供“重试失败卡”，未知回执提供“核对并继续”，不能两个按钮都触发重买。Puzzle 继续从当前原生概念槽开始，仍支持不是 FCAT 生成的阵容；重试时必须重读当前槽位，手动改阵不能被历史清单覆盖。

### 4.3 重试页面建议：在原结果列表直接修改本次上限

本节已由用户于 2026-10-04 选择“采用该方案”确认，现已实现原窗口共享重试组件，验证与剩余实机边界见 §11。它是本次新增的采购交互，不将它描述为 FSU/Enhancer 原版已有行为。

默认流程：批次结束后保留原前台购买清单；成功卡折叠为结果摘要，失败卡展开。无需跳转 Settings 或 Tools，不增加第二个确认弹窗。

每张失败卡显示：卡面/版本、两源参考价及更新时间、上次购买上限、失败原因和已尝试次数，以及可编辑的“本次重试上限”。不把该输入命名为“购买价格”：它是允许支付的最大值，实际会选找到的更低合规挂牌。

| 卡片 | FUT.GG | FUTBIN | 上次上限 | 失败原因 | 本次上限（可编辑） |
| --- | --- | --- | --- | --- | --- |
| 示例 A | 200 | 250 | 200 | 3/3 次，上限内无挂牌 | 300 |
| 示例 B | 950 | 900 | 950 | 3/3 次，挂牌已失效 | 950 |

底部显示“已选 2 张 · 本次最多 1,250 金币 · 每卡最多 3 次”，并提供“重试所选失败卡（2）”和“关闭”。同一页面另显示此前累计实际支出及剩余总预算，不能把 1,250 标为预计实际成交金额。重复点击不会发起第二批。

具体行为：

1. 默认勾选明确未成交、可重试的失败卡，沿用上次上限；用户可以直接原价重试，不必修改任何字段。已成功、已买未入库、未知成交不能进入失败重买清单。因用户停止而尚未处理的卡单独提供“继续未处理”，不能谎报购买失败。
2. 上限可以逐卡改，也可用紧凑的批量控件按当前有效参考价加固定金额或百分比，应用到所选卡。此控件不自动提高金额；每次点击应用都以参考价计算，不基于已经提高的上限复利叠加。
3. 手动上限是对本次选中精确版本的明确覆盖，可高于 Settings 的默认溢价结果；否则允许编辑没有实际意义。它不修改账号默认值，仍受账号显式绝对单卡上限、预算、余额和 EA 合法范围约束。不能按卡片名字或基础球员 ID 将覆盖价扩散到其它版本/方案。
4. 编辑立即更新单卡有效上限与整批最多支出。非合法档位、超过绝对上限或所选上限总额超过剩余预算时就地说明，用户调整后再开始；不能静默放宽、向上取整或先买一部分才暴露输入矛盾。
5. 显示现有有效缓存的两源价格和时间；提供“刷新参考价”，只刷新这些失败卡并合并请求，不预查 EA 全市场。刷新不会覆盖手动输入或自动抬高上限；用户可主动应用按新参考价计算的金额。报价过期/所选源缺价时提示更新或调整 Settings 来源，不用 EA 值兜底。
6. “重试所选失败卡”本身就是对当前可见清单、上限和次数的明确批准。点击时冻结本批条件；后台刷新、设置改变、切页不能扩大已批准金额。当前失败项新一轮重新得到配置的尝试次数，同时保留历史次数；刷新/重载不会自动重置并执行。
7. 失败原因若是“上限内无挂牌”，不能写成“涨价至 500”或建议用户付 500，除非有真实挂牌证据；即使有上次 EA 搜索证据，也只能标注“上次可见挂牌”，不能把它作为参考价或自动填入上限。
8. 已买入但入库/替换失败时提供恢复操作，不能编辑价格后重买；未知回执仍显示“核对并继续”。重试前按当前 Gallery 收集/持有状态或 Puzzle 概念槽核对，已被用户手动补齐的版本跳过。
9. Gallery 与 Puzzle 共用价格编辑和结果状态组件；Puzzle 从原侧栏按钮进入当前前台结果，不跳到 Tools。手机/窄屏按卡逐行展示，保留上限输入和底部重试按钮。

建议例子：参考价 200，原上限 200 未买到，用户输入 300 并点击重试。若找到 250，按 250 成交；只有 500 的挂牌时仍失败，不会因为用户点过重试就允许 500。若用户保持 200 不修改，点击重试只是重新寻找 200 以内的挂牌。

新增验收：失败卡默认选择与成功卡排除；未修改直接重试；逐卡/批量上限与总额联动；刷新参考价不覆盖输入；溢价不复利；绝对上限/预算/档位冲突；未知回执无重买入口；手动补卡后跳过；连续两次主动重试次数可追溯；双击、刷新、换号不扩大授权。此交互纳入 P3，工时仍在 P0 结合组件复用与场景数复核，不宣称现有草稿已经支持。

## 5. 挂牌：以 Enhancer 为唯一行为基线

参考文件：`artifacts/fodder-research/enhancer-index-readable.js`。已定位 `Qh`（设置）、`Yh/fMt/dMt`（控件）、`gMt/yMt`（计算与选择）、`xAe`（执行与进度）。实施前完整追踪其调用的取整、价格档位、随机数、价格范围和 listItem 实现，记录源码版本/hash及可复用部分的许可/归属。

优先提取原有公式、状态更新和可复用 UI 代码；因 React/Base UI 与当前 DOM 实现不同而必须适配的部分逐项列出，不能用“已参考”掩盖不同的行为。受源码许可约束不能直接搬运的部分在实施前明确说明，不把可读源码当作已获授权。

### 5.1 必须一致的行为

| 项目 | Enhancer 已观察行为 / 验收要求 |
| --- | --- |
| Percentage | 单个双滑块，0–200；默认 100–100；两个数字框双向联动，端点不能交叉 |
| 两个百分比的含义 | 每张卡挂牌比例的随机范围，不是最低起拍价与最高一口价 |
| 百分比价格 | marketPrice × 原版随机比例，再按原版 roundToNearestStep 取整；不能使用购买成本或 EA 搜索价替代 marketPrice |
| Fixed | Start Bid / Buy Now 的原版输入联动、空值和价档行为；固定金额仅本次会话，不恢复成持久设置 |
| Steps | 使用原版价格档位算法及 -20…20 控件；不是对金额简单加减固定数 |
| 起拍价 | 非固定模式由最终一口价取前一档；最低档边界由原版 helper 与 EA price limits 决定，不猜测 |
| 选择与重新计算 | 选择卡片不重抽价格；价格设置改变立即重算；单卡覆盖的保留和触发重算时机按原版 useMemo 依赖逐项回放 |
| 默认选择 | 原版为可交易且有报价的卡；其它卡的可选性/手工定价按原版核对，不擅加过滤 |
| 执行金额 | 预览冻结后逐卡执行，不能点击挂牌时又随机一次；实际请求的 Start Bid/Buy Now 必须和预览相同 |
| 进度 | 原版前台清单、当前处理卡和逐卡完成/失败/跳过；按原版等待范围逐卡执行 |
| 失败 | 原版明确单卡失败继续；FCAT 既有未知回执、账号锁、精确身份恢复是已存在差异，单独标注，不隐藏成完全相同 |

示例：参考价 1,000，Percentage 固定 90–90，应产生 900 的一口价；该区间前一档若为 850，起拍即 850。80–100 是每张卡独立得到范围内的比例再取整；最终结果必须能用同一随机序列在原版和 FCAT 中重放一致。

### 5.2 购价、卖价、利润分清

- 挂牌参考价明确为 FUT.GG，不继承购买溢价；真实买入价来自精确成交回执。
- 不把 `lastSalePrice` 自动当作本次真实购入成本；没有成本证据显示未知。
- 展示参考价、起拍价、一口价、已确认购价、预计税后盈亏。税费取整沿实际规则核对。
- 无报价、报价过期、价格范围失败和越界分别显示原因，不能静默改成另一来源或不同金额。
- 不把“挂牌成功”当作“已经售出”；本计划不新增自动售出/重挂调度。
