# 同一次搜索先买后处理

## 已确认范围与计划（2026-11-15）

用户在已说明Enhancer与FCAT差异后要求“继续借鉴Enhancer”，采用上一轮建议：每次搜索默认1/可配置N，低价优先，先串行处理本次最多N个候选，再移卡/挂牌；保留原逐笔价格/预算/持仓检查与未知成交保护。仅持有仍只移Transfer。不是全面替换为Enhancer交易器，不改变已批准的买卖规则、请求间隔或错误分类。

参考链：本地Enhancer27.0.0.4，30154 handleTransferResultsBG → 7520检查 → 83847 bid → 8119 handleWonItems → 2113卖出处理中间件。源码哈希及逐项差异见FC27_TRADING_HOLD_ONLY_ZH.md。原版按返回顺序，失败response=true也计处理数；本地保留已批准的低价排序与最多N个有效挂单，不承诺成功买满N张。本轮不复制参考源码、不引入其运行依赖。

实施步骤：
1. 生产组合回归先红：一次搜索返回多挂单，预期search/buy/buy/buy之后才move/list。
2. provider优先处理当前搜索剩余挂单；不开始下一次搜索，直到当前已购卡处理完成。过期/不满足原版本上限跳过；已明确拒绝继续原候选，未知/认证仍原暂停。
3. 所有任务已购但尚未移入Transfer的held实体预留槽位，原锁内逐笔核余额/预算/持仓。容量或额度不足且有本任务已确认待处理卡时结束本批，先移卡/按原卖出时间挂牌，再显示原限制；定时满额仍关闭本轮买入。无新发送或未知证据不得被本批收尾覆盖。
4. 每笔继续原调度轮转，保留其他任务机会；首笔search→buy原同锁快路径不变，后续购买仍走原鲜读/节奏。不在后台新增无上限抢购循环。
5. 暂停/停止不移卡、不清Journal，已发请求照原流程结算；显式再启动先处理已购卡，再重新搜索，不复用旧挂单。编辑/刷新同理。卖出专用任务不变。

## 场景与验收

| 场景 | 预期 | 验证 |
|---|---|---|
| 1与多挂单、普通挂牌/仅持有 | 上限内按低价串行买完再处理，hold无list | 生产组合/Chrome |
| 明确竞争失败 | 不重复原挂单，继续本轮后续候选，不强求补满 | 生产原生组合 |

| 剩余1个位置但有多挂单 | 只买1张，先移完，绝不超买 | 生产组合/协调器 |
| 支出/持仓/留存不足 | 先收尾已确认卡，再给出原限制，无额外买入 | 生产组合 |
| 到买入截止/版本上限/报价过期 | 不再买当前旧挂单，仍处理已确认卡 | 生产组合/定时测试 |
| 买后暂停/停止/再次启动 | 当下无后续写，再启动不重买已确认卡 | 生产组合 |
| 两任务 | 逐笔轮转、持仓和额度隔离、共享容量 | 生产组合 |
