# FC Automation Tool 27.0.21

基于 main `97f1dc0 / 27.0.20`。用户打开当前主阵容后仍在生成方案前报
`FC27_STREAMLINED_PROTECTION_UNVERIFIED`；原日志缺具体失败阶段，根因未确认。

## 变更

- 同一保护错误增加八类固定阶段：Lock 名单、active ID、native ID、layout、slots、
  slot item ID、FSU roster、已绑定缓存；只保留有界类型、数量、索引和缓存布尔状态。
- Session 在规划失败时保留这些证据，既显示在面板，也进入原诊断导出。
- 结果区与按钮旁显示中文原因/下一步，原错误码与阶段仍保留供定位。
- 不输出账号、物品 ID、原生对象、URL、凭据或源码；未知阶段/任意字段均丢弃。
- 保护判定、读取路径、采购/贡献/恢复及旧 Journal 保持原样；没有新增 EA 请求。

## 证据与限制

- 修复前的 Reader、Session、消息回归三项均失败；修复后通过。
- 现场两份 JSON 证明规划前被拦，不能区分究竟哪个输入缺失或异常；打开主阵容
  仍失败也不足以证明是原生缓存被清除。下一次新诊断仍是定位真实字段的必需证据。
- 2026-10-14 匿名读取公开 compiled_2.js HTTP 200，SHA256
  `2cc8aec08628ea78c361b16456c93d672e1e80219ed246af0ace61f1b1018f83`，与已保存版本一致。
  本机浏览器连接报 request-header policy 错误，未读取当前账号运行时对象。
- 不将本轮诊断增强称为实际运行修复；未代用户购买、移动、献祭或清除状态。
- 完整 `VITEST_MAX_WORKERS=2 npm run verify`：413 文件，4658 项通过、39 项跳过。
  原测试时限未改；root/dist 1,807,401 bytes、SHA256
  `ad2e7e4e0aa9bd6c1a14249ebbd79a84d294af9a6b1627e079f931bca248d7f0` 一致，FSU 仍为 26.09.10。
- 全套离线 Chrome 回归通过；旧 27.0.20 面板回放在新保护提示断言上明确失败，
  当前面板通过，覆盖结果区/按钮旁中文提示、原始码保留，以及零报价/交易/设置写入。
- 新模块仅作证据白名单裁剪；只读 inspector 的依赖白名单明确纳入该模块，
  未扩大为事务依赖。真实报错字段与实际运行恢复仍待用户更新后验收。

## 更新后

安装 [main 27.0.21](https://raw.githubusercontent.com/ShatteredLancer/FCAutomationTool/main/FCAutomationTool.user.js?v=27.0.21)，刷新 EA 页面后核对版本。
只点一次“生成方案”，若仍被拦，保留新中文提示并导出诊断；不要解除锁卡或删除旧记录。
只按用户批准推送 main，不创建 tag/Release。
