# 27.0.80 — 清空阵容后的旧方案失效

## 修复

- 原逻辑在页面阵容为空时会重新解题，但只跳过当次旧方案恢复，仍将终态草稿保留为可恢复。若重算失败，后来打开旧服务器阵容时，旧草稿可能再次被报告为已恢复。
- 用户清空阵容后再次点击解题，原已确认保存的概念草稿现在记录持久失效标记；旧保存证据仍在，但不再恢复显示、不再从该草稿回填库存预留。新方案成功保存后正常替代旧草稿。
- 失效检查只需同账号、同挑战的原生页面布局，不依赖新选材设置有效。因此新设置导致重算失败，也不会让旧方案重新生效。
- 重新打开非空原生阵容时提前明确阻止覆盖，不再先对它进行无用的选材/查价。普通有效草稿的精确恢复与未确认保存的只读核对保留。

## 保留边界

- 不删除或修改购买成交凭证、待核对买入/移动/保存记录、其他 SBC 的记录、锁卡或设置。失效标记矛盾、格式异常或与未决保存并存时仍阻断。
- 没有通过猜测用户操作去覆盖或清空 EA 服务器阵容；失效在下一次当前页面的显式解题操作中记录，不是后台替用户执行 Clear。
- 方案记录、候选球员资料缓存、参考报价是不同对象。本次没有批量清除资料缓存、延长报价有效期或调整预算/单卡限价。

## 与昂贵方案问题的区别

用户提供的本机备份中，安装的 .79 脚本与发布文件哈希一致。该轮诊断显示重新执行了求解，而非仅恢复旧方案；当前三次资料查询有缓存命中。离线重放发现本轮有价候选只覆盖 65/75 分，较便宜的 76–85 分俱乐部结构未进入该候选池。这是另一个候选覆盖问题，不能用本次失效修复宣称已经解决。

历史资料能给出更便宜的结构，但部分资料已经过期；不得将历史估价当作当前可买价格，也不得跳过原生资料和现价复核。

## 回归与验收

- 两个先失败的回归：概念会话“清空→重算未保存→重开旧阵容”，以及实际页面 reader/planner/session/provider 链路重启后不得恢复旧方案。
- 覆盖新方案成功替换、坏选材设置后的持久失效、兄弟挑战不复活旧预留、失效标记矛盾/时间非法、未知保存不清除、五笔既有成交凭证不改写。
- 用户备份中该挑战的真实终态草稿离线回放通过：只改内存中的当前草稿键，原计划内容逐字段保留；再次恢复和预留读取均不复活，provider 调用 0，原备份文件哈希不变。不是实际 EA 状态或当前价格的验收。
