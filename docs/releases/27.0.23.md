# FC Automation Tool 27.0.23

基于 main `5349226 / 27.0.22`。用户批准调整 Streamlined 积分解题的报价层，
并提交/推送 main；不是重写 ad 的积分优化、采购或贡献主流程。

## 问题与本次合同

现场 .22 已能通过保护检查并生成方案。后续 FUTBIN 156 个版本读价耗时约
181 秒；一处实际请求超时触发来源熔断，逐卡错误包含后续跳过，并非每条都联网
失败。原混合方案因任一来源错误整批停止；读取返回与有效覆盖又分别记 success/
failed，容易误判。本次明确改变的是报价失败隔离，不是取消来源/库存保护。

- 一次规划从报价准备开始共用 90 秒截止时间：库存、市场、过期报价刷新和缺版本
  单卡补读不各自重置预算。同评分批量入口、最多 3 个 FUTBIN worker、同版本去重、
  来源熔断及有效缓存复用仍保留。到期返回当时已验证的独立快照；后台已有请求
  保留队列所有权并正常收尾，不因 UI 返回释放锁或启动重叠请求。
- 90 秒限制的是公共报价等待，不是 EA 候选目录/积分读取、优化搜索或买卡总耗时。
  已发出的报价请求仍需完成既有网络超时/收尾。截止时间不是新的网络故障，不写
  来源故障 cooldown，也不启动后续分页/版本补读。
- 有效报价须为同来源、同精确版本、正整数价格且未过期。失败/缺失/过期版本
  不参与待确认方案；未知不是零价，不自动切到另一来源，不延长旧 fetchedAt。
- 部分报价仍可生成已知候选方案，显示库存/补卡版本有效、失败、缺失/过期数量，
  明说不保证全库存/全市场最低价。报价减少可能导致方案更贵，不能称为完整最优。
  用户先核对现有库存消耗/价格，再勾选接受，随后另行点击执行。切换路线/重新
  生成/恢复后重新确认；quoteLimited 冻结到方案指纹和 Journal，不自动解除。
- 市场候选身份/目录失败、来源禁用、账号/页面变化仍停止。只有已验证市场候选
  报价全部不可用而库存报价有效时，才显示有明确覆盖限制的库存方案；没有任何
  有效报价时仍无方案。用户原材料范围/目标不静默重写。
- 诊断把“读取完成”与“有效覆盖”分开。库存报价阶段仅记一次验证后的
  success/partial/failed；市场覆盖也独立记录，不再将请求返回记为报价全部成功。

## 不变

账号公共报价选源、FUTBIN/FUT.GG 原始端点、报价时效、冻结单卡上限/预算、
手动 Lock、主阵容首发/替补/预备、EA 资格/积分、请求前复核、事务/恢复主逻辑
以及 FSU 26.09.10 不变。Gallery/Puzzle 不传截止时间，保留原报价读取合同。
不操作用户账号，不清旧记录，不创建 tag/Release。
