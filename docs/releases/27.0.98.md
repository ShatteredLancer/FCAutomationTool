# 27.0.98 — EVO 消息仓与 304 缓存读取兼容

## 怎么用

1. 更新脚本并刷新 EA Web App。打开 **交易观察 → 候选与线索 → EVO 消息仓**。
2. 粘贴具体 X 帖子，点 **读取帖子并核价**。这一步会按需调用本机 Grok，可能产生费用；同帖 15 分钟内使用采集缓存。
3. 查看原文、来源买入上限、精确普通卡版本、同平台 FUTBIN/FUT.GG 报价、审核目标和风险。点 **纳入整批方案**，不会立即买入。
4. 回 **投资与执行**，设置本轮上限/留存，重新生成清单、审核并明确启动。消息仓与价差策略共用总预算；每版本一张、整批最多六张，不要求用满额度。
5. 消息仓买入并确认转入 Transfer 后先持有。保持本页运行时，双源参考都达到审核目标，才按该固定目标上架一小时；上架不算成交或利润。

本机采集器也需使用更新后的项目文件。后台管理仍是 `npm.cmd run trading:intel:stop` / `npm.cmd run trading:intel:start`；已有配对码保留。它只在显式采集时调用模型，不负责后台执行 EA 交易。

## 价格和信息边界

- 支持显式导入名单外作者的**单条帖子**，不把该账号自动加入原有五个常规采集源，也不赋予准确率或低风险评级。
- 仅核对请求的原帖及最多三条同作者回复；保留原始时间/雪花 ID、原文和实际原生 X 工具证据。线程可能不完整，EVO 完整条件和最终适配仍待核实。
- 原文明确报价且逐字引用可验证时才接受上限。支持 `1.5K` 和阿拉伯数字；截断单位/数字不算证据。不识别的说法保留为观察线索，不猜价格。
- 名字搜索须唯一成功；同名歧义或版本不明保留为线索。首版只处理唯一普通卡版本，特殊版本不按姓名替代。
- 来源建议、当前参考价和审核目标分开显示。没有来源卖价时，目标只按现有税后利润/缓冲计算，是情景门槛，**不是涨价预测**。
- 买入硬上限同时受来源严格 `<`/`≤`、当前双源低值、单卡上限、总预算及留存约束。旧价差行的现价/盈利门槛保持不变，不借消息仓绕过。

## 自动上架与防重

- 消息仓首次审核包含在当前页面持续触价监测的授权，六小时后停止并提醒复核，不自动亏本止损或延长旧授权。
- 停止、离开交易页、重载、检测到账号变化均取消监测。重开仅恢复记录，重新审核继续后才重新启动；A→B→A 不恢复旧触价授权。
- 触价授权绑定冻结方案 ID，并在执行锁内与当前 Journal 对照；另一窗口更换任务后，旧计时器无权处理新任务。
- 自动触价执行只处理已确认持有的事件卡，不重买、补买或重发未知上架。买/移/挂先持久化意图并回读，再发请求；未知结果仍按原流程只读核对。
- 来源失效、移除或同 URL 的版本/上限/报价依据变化撤销后续写权限。只读读取已上架成交回执不受来源失效阻断。
- 事件元数据单独按账号保存，最多六条/60 KB，不存整目录。跨标签锁内核对递增 revision，迟到的采集结果不会复活已移除线索。全部原交易 Journal、锁卡与设置保留。

## 现场 304 问题

.97 的 14:50 诊断证明：未分配读取已 `completed` 且业务成功，返回 304，却被交易前置校验误拦；当轮确认买入仍为零。另一次 `REFERENCE_CHANGED` 属于独立的报价保护，继续保留。

经既有 EA DAO/Repository 来源核对，只有已初始化、完整、未过期、非 dirty 且 getter/count/entity 一致的对应 pile，才把业务成功 304 当成**读取缓存有效**。缺状态、失败、过期或异常缓存仍停止。

买/移/挂的后置回执不接受 304 冒充新结果。沿用原生买家已使用的 `setDirty(PURCHASED)` 刷新方式，仅将相应本地 pile 标为需重读，取得独立 2xx 后继续精确实体和挂牌/成交校验；不变更真实库存、不重发交易。价格边界和售出回执没有新增 304 特例。
