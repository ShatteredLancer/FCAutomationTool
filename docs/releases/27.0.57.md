# 27.0.57 — Read-only listing reconciliation, without duplicate listings

- Add up to three read-only Transfer refreshes, with 1/2-second backoff, when an owned entity or auction is temporarily unavailable. Permanent identity/price conflicts remain unresolved; authentication/session/rate-limit failures stop the check. A failed HTTP refresh cannot confirm cached auction data, even if its adapter label says completed.
- Recognize an ended auction only with the exact entity, Transfer location, frozen starting/BIN prices, valid auction ID and a durable successful 2xx listing acknowledgement. This confirms a listing, not a sale or sales revenue.
- Reuse the same evidence rules for immediate readback, explicit recovery and old-batch reconciliation. Neither retries nor recovery call list/move again for the unresolved item. Unknown, missing or conflicting evidence stays preserved.
- Show read-only check progress and distinguish an ended acknowledged auction in the result. Diagnostics add fixed mismatch reasons, attempt counts and HTTP status without account/item/trade identifiers.
- No changes to selection, approved prices, EA limits, ordinary listing delays, cross-tab locks, budgets or Gallery collection history. Includes the storage improvements from 27.0.56.

The supplied 27.0.55 export omitted the failing readback fields. The delayed-visibility and closed-auction defects were reproduced independently at the real Session boundary; these fixes do not establish which one caused every historical failure. Live acceptance of the user's old journal remains pending after updating; no live purchase, listing, move or clearing operation was used for testing.
