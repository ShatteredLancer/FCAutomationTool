# 27.0.71 — Keep usable Gallery routes through planning deadlines

- A planning deadline or Stop no longer publishes an empty comparison over an already usable global plan. Retained selections are rechecked against current exact options, ownership baselines, cash assumptions and limits; changed/expired candidates are withdrawn rather than reused as valid.
- Global comparison uses resumable, frozen candidate generations and 40ms cooperative slices. New collection candidates coalesce into the next comparison instead of restarting the active cursor. Collection calculation continues between comparison slices. The confirmed S → A → B priority and bounded global heuristics remain.
- The first verified route provides an explicitly labelled baseline for all three alternatives while their independent comparisons continue. A weaker checkpoint does not replace a stronger still-valid incumbent under the selected objective. No mathematical or whole-market optimum is claimed.
- Export now reconciles local collection changes before deciding whether to include the retained plan. A small `planningState` explains unavailable/retained results; invalid account/catalogue context is still excluded. Forecast and independent quote freshness remain separate and unchanged.
- Diagnostics retain 20 sanitized roadmap events independently of the existing shared 40-event performance ring, plus a planning checkpoint no more than once per five seconds. Pricing traffic therefore cannot evict the entire retained roadmap trail. No account IDs, credentials, native item objects or large planning snapshots are added to GM storage.

Evidence: the old production path first failed deterministic unit tests and the offline Chrome export scenario. A local 196-collection/6,700-version snapshot with older cached public estimates reproduced 52/72 targets being overwritten by an empty deadline result; the updated path retains valid results. In the same controlled 1.5-second first slice, inspected collections increased from 154 to 196 (not completed collections or live-account speed). The original frozen planning inputs and exact market prices were not exported; this is not an exact live execution replay.

Actual buys/listings, balance checks, budget/single-card limits, FSU/locked-player policy, transaction journals and recovery are unchanged. No real trades, submissions, claims or script installation were performed in this release check. Same-tab retention is not cross-refresh persistence.

Final frozen-source validation: `npm run verify` passed 439 files / 5,273 tests (39 skipped), including syntax/no-undef/configuration/architecture/FSU patch and root/dist/release-asset checks. The complete offline Chrome suite passed, including the added material-change-to-export workflow. Desktop and 390px screenshots were visually inspected. The initial default-concurrency full run hit two unchanged 10-second Streamlined test timeouts; the final full run used four workers without changing test timeouts or transaction tests.
