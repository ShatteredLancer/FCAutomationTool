# 27.0.103 — Streamlined 明确拒绝批次的续做

## 现场证据与上版遗漏

27.0.102 的新诊断确认：原任务与2张已购卡已成功恢复，但随后三次在 `contribution-preflight` 返回 `FC27_STREAMLINED_REPLAN_REQUIRED`。积分仍为10,550/16,000、已花3,500金币、6张已确认贡献，未再购买或贡献。

上版只复现了外层采购任务身份冲突，其测试中的贡献桥接仍被替身简化；真实内层贡献Journal还保留第三批401的明确拒绝状态。相同批次重新执行时，通用事务将 `rejected` 当作必须重新规划，恢复则只能报告未提交成功，形成第二个死循环。

本版在修改前新增两条失败回归：真实采购桥接/贡献事务重复同一批次，及 Session→Procurement→采购桥接→贡献事务/双Journal 的完整合成路径。旧代码均复现本次 `REPLAN_REQUIRED`，不以扩大节点、预算或刷新登录代替修复。

## 修复范围

- 仅生产采购贡献桥接显式启用已拒绝批次续做；普通手动贡献仍保持原规则。
- 再次执行必须持有原事务锁和新的明确点击授权，仅精确同一计划身份、单批次、`rejected`、无成功回执/积分漂移、起始积分等于当前已确认积分时可以重建待执行批次。账号、目标、材料、政策、原上限均包含在冻结计划身份中。
- 重建前完整归档旧拒绝Journal并验证回读、校验旧revision；归档冲突、失败或丢写时停止，原活动记录不变。
- 重建后仍逐项 fresh 核对材料、身份、锁卡/主阵容、规则、进度、有效期及写权限，再写意图和发送。每次点击只尝试该批次一次，不后台循环重发。
- `pending`、`unknown`、成功/已确认、有成功回执、不同计划、不同积分及无明确发送起点的记录都不按此规则重启；只读恢复仍不贡献、不购买、不移动。

外层采购累计支出、总预算、单卡冻结上限和授权池不变；已确认6张不重投，2张已购卡先核对后继续。保留27.0.102的原任务恢复入口和ad 27.0.101的Puzzle/Gallery/归档逻辑，不修改交易功能、FSU或原生方法审查。

更新后刷新，在原SBC点“生成方案”或“核对并恢复”，再点击“继续原方案购买并贡献”。若后续真实核验仍失败，应保留记录及诊断，不清空历史或重新买入这2张已购卡。
