# 27.0.54 Puzzle roster protection and price-label correction

## Evidence and fix

The new-account Set 65 / Challenge 105 screenshot includes LB Balde from the user's active squad. In 27.0.53 Puzzle policy disabled both FSU locked-item and active-squad protection, while Club snapshot item flags are unknown. The supplied diagnostic confirms a concept squad was saved but does not export the selected private item IDs. The source path explains why the card was eligible.

Puzzle planning now reads exact FSU lock IDs and the native active squad's full 23 slots, using the same verified protection reader as Streamlined. Protected IDs are excluded from safe candidates even when Club item flags are unknown. A missing or drifting protection snapshot blocks planning or later fill/save verification. Traditional Runner behavior is unchanged. Read-only browser bundle allowlists were reviewed for the extracted protection leaf module.

Existing SBC squads already saved on EA are not retroactively cleared. The user should clear the old saved squad and regenerate after updating; the new protection applies to the new plan and subsequent checks.

## Cost boundary

The shown 2,850-coin estimate is *additional purchases only*, not the squad's full market value. The current solver treats owned cards as zero incremental spend, searches a bounded candidate pool and does not prove a global cheapest solution. A screenshot showing about 8,900 total squad valuation versus a lower third-party all-buy estimate is therefore a useful signal but not a like-for-like price comparison. UI text now labels incremental spend, excluded owned-card value, and missing global-optimality proof. This release does not change the search objective, catalog/quote coverage, node budgets, frozen buy limits or transaction behavior.
