# 27.0.33 — 积分贡献前 Storage 读取兼容

## 原因与范围

用户在 27.0.32 生成了含 Storage 的纯库存方案，贡献前材料校验返回
`FC27_TRANSACTION_METHOD_UNREVIEWED`。本次请求尚未进入贡献发送步骤。
旧诊断只保留阶段/错误码，没有具体方法路径和指纹。

独立匿名读取 EA 当前公开脚本可复现同码：共享 HTTP 方法检查通过，
Storage `searchStorageItems` 和 `setUrlVariables` 仍只认可此前的实现。
当前两个实现已核对只读契约：GET `/storagepile`，查询 `skuMode=FUT`，
筛选为本地操作；原生缓存分支返回 304。本工具仍发起自己的新鲜读取，
不调用原生缓存路径或继承其缓存写入。

## 修改

- 仅向 Storage 只读 Adapter 增加两个已核验的精确兼容指纹；旧实现仍接受。
- 未知函数、初始化后替换、账号/接口变化仍拦截，不放宽共享写事务检查。
- 贡献/恢复诊断补传固定方法路径、观测 hash 和预期 hash；沿用脱敏白名单，
  不输出方法源码、原始响应、账号、物品/成交身份或凭据。
- 保留 27.0.32 的库存优先、全部 FSU/锁卡/进化/主阵容保护、预算、
  旧 Journal 和未决回执；不改 Gallery/Puzzle 或实际贡献请求/重试。

## 验证与证据边界

- 当前公开方法使用真实 SHA256，而非伪造现代方法 hash 的测试映射；
  原始文本和解码字符串在日期标注的公开源码 fixture 中。
- 原生方法重放验证 GET/查询/本地筛选/缓存 304；本工具验证一次新鲜
  Storage 读取、重复版本实体、拒绝未知替换及不扩大共享验证许可。
- 生产贯通：混合 Club/Storage 材料校验 → 合成贡献 → 新鲜读回 → 本地
  收尾 → 再次恢复，不重复贡献；只读进度与贡献方法当前指纹未变。

  Storage 检查均通过，未登录、未访问账号交易接口。

  这 4 文件独立复跑 133 项通过。设置进程内 `VITEST_MAX_WORKERS=2`

  `c2298454588ec4a82e72c24c71e31ee01bf09eeb48b2e1b4c667408c442ef51c`。
