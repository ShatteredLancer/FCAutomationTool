## 修改

1. 有俱乐部总数上限、正默契要求、多数单品质要求，且同联赛上限低于该品质数量时，优先跨已知俱乐部/联赛发现该品质；允许低品质的安全俱乐部材料作为新查询方向，而非把低品质算作满足需求。
2. 已饱和联赛后置。所有已知俱乐部都在饱和联赛、品质容量仍不足时，保留一条该品质的宽查询。保留原三页/每页20上限、去重与 usedQueries，明确指定俱乐部/国籍/联赛的路线不被覆盖。安全候选仍由原 FSU/锁卡/主阵容/评分等筛选产生，受保护卡不作为新方向锚点。
3. 搜索将每个至少/恰好数量谓词与同组最多/恰好上限联动。按剩余组空间与匹配后缀数量取小值，再跨组求和；容量仍达不到下限就剪枝。例如七张金卡全部在同一联赛，但每联赛最多四人，不能因目录里有18张金卡就继续组合。
4. 该界刻意忽略其他冲突、允许物理重复在后缀中多算，只可能高估容量；去重、原生条件和完整阵位/评分/默契验证仍在。零容量组不留在索引，达到所需容量后立即结束统计，减少额外开销。不宣称局部不足等于全市场无解。
5. 不提高搜索上限，不改报价来源/有效期、预算、单卡限价、库存保护、交易审批、未决记录、购买/移动/保存/提交或 .80–.82 的修复。
