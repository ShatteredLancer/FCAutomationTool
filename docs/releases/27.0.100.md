# 27.0.100 — 国籍上限候选纠偏与分段解题预算

## 现场依据

2026-11-06 的 .99 诊断：Set 108 / Challenge 162，当前快照 95 项经过原材料保护后可用 0 项；初轮三页候选为俱乐部金卡、同一国籍金卡第一页/第二页，59 个公开版本中 48 个可用。50,000 节点全部用于组合枚举，阵位和完整验算均为零。

## 候选策略

- 仅在“指定俱乐部＋同俱乐部最低人数＋国籍上限＋多联赛”这一组合约束下调整候选查询顺序。先核现有俱乐部候选是否能共同覆盖国籍容量与阵位，再补宽页/欠覆盖的其他联赛，不连续加深已经受限的主国籍。
- 俱乐部支撑使用“国籍容量→精确版本→阵位”的联合匹配，不把两个独立上界误当可用骨架；支撑不足时保留 OR 另一俱乐部的查询机会。
- 仅改变查询方向，不强制某俱乐部/国籍/联赛入阵，不过滤掉其它合法解；最终仍由完整 EA 条件、评分/化学、唯一版本和材料保护校验决定。
- 初轮仍为最多三页、每页最多二十项，已有低价细化范围不额外扩大。重复页不再读取；未覆盖市场仍明确为有界采样，不承诺全市场最低或穷尽。

## 节点、进度与取消

- 生产补卡的联合可行性搜索启用累计 50,000→100,000→200,000 节点账本。阶段扩大时不从根重启同一棵 DFS；质量偏好/原生回退、不同搜索起点和初轮候选页共用计数，不是三轮相加 350,000。
- 发现完整可行阵容后不再为扩段而硬跑下一档；已有可行方案的固定小预算降本/修补保持原范围。原来显式指定固定节点上限的离线/工具调用不被偷偷放大。保留报价过期、上下文改变和最终完整验算的停止条件。
- 界面显示累计节点、当前阶段 1/3–3/3 及总上限 200,000；诊断增加固定数值阶段，不增加历史容量或导出私人库存。
- 计算/查询阶段显示“取消计算”，使用原协作检查停止后续工作，不填阵保存。进入复核/保存边界后隐藏取消，避免把已经发送的保存请求误称为可撤回。切换目标、离页和销毁仍停止旧计算。
- 本地取消不再把已成功读取的目录/报价改写成永久网络失败；仅本次精确匹配、明确未发送的只读 pending 可标记取消后重试。不同账号、外来 pending、401/429/503 和实际网络失败仍沿用原隔离/退避，不清理或重试交易 Journal。
