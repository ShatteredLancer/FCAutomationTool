# 27.0.78 — Gallery background planning and Puzzle cost/retry recovery

- Large Gallery detail pools no longer prefetch every display quote before planning. More than 64 unique versions defer display-only pricing; explicit planning retains its selected-source policy and 90-second shared quote deadline. Small-club display pricing is unchanged. Planning parameters were already forwarded correctly; the eager display job was occupying the same queue.
- Gallery cooperative computation now prefers ordinary MessageChannel tasks through the existing helper instead of a zero-delay timer. A full regression caught native scheduler.yield continuations delaying timers for more than a second; ordinary message tasks preserved the same cost replay with roughly 80–100ms maximum heartbeat gaps. Native yield/timer remain compatibility fallbacks. This addresses the supplied .77 run with 112ms processing but 224,446ms scheduling; quote expiry and input/account invalidation still stop stale work. It does not guarantee progress in a fully suspended tab.

- Puzzle opts into a bounded, per-run exact rejected-listing filter before the FSU-style price walk. Explicitly rejected stale offers are not selected repeatedly while another approved-price offer exists. Existing attempt allowances, pacing, caps and budgets remain unchanged; unknown responses and HTTP401/403/429 do not authorize automatic rebids. Other users of the shared adapter keep their existing defaults.
- A precise known-Club-only concept-replacement delay no longer hides failed-card retry. Confirmed purchases stay non-selectable; unknown payment/move/save states remain recovery-only and the executor repeats all checks. Bid/move response codes and filter counts enter the existing redacted diagnostic stream without auction identities.
- Monetary Puzzle searches compare cheaper native-valid quality mixes even when the preferred low-quality composition is feasible. The incumbent is retained unless strictly improved; ties retain the low tier. Both phases share the existing node ceiling. Non-monetary owned-only preview behavior and all material protections remain unchanged.
- Expensive feasible squads with a native rating target up to 75 use a remaining refinement lane for a permitted lower-quality connected league, instead of only deepening gold pages. Three catalogue pages remain the ceiling, explicit all-gold constraints remain binding, and no FUTNEXT runtime dependency or new remote is added.

The supplied .76 case recorded seven purchases and one listing-unavailable result within a 1,000 cap; the user bought manually within that cap. Missing bid codes prevent exact attribution of its original receipt. Offline controls reproduce repeated stale-offer selection and the replacement-only retry UI defect. Public FUTNEXT Set78 pages were inspected after the user identified Marquee Matchups: one Liverpool v Arsenal example shows a 5.2K, rating75/chem26 squad using five gold80 and six bronze cards. A synthetic same-requirement-shape Session improves 8,800 to 5,200 within three pages/50k; a separate pool-only control improves 5,200 to 4,850. Neither is an exact replay or verified saving versus Viva's unavailable original squad, nor a live-market price guarantee.

No real EA purchases, moves, saves or submissions were used for testing. FSU stays 26.09.10; .77 Gallery quote deadlines/wide-pool witnesses, locks, active-squad protection, approvals, budgets/caps, journals and unresolved records are preserved.
