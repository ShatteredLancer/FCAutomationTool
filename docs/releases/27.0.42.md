# 27.0.42 Historical purchase isolation for stock-only recovery

## Evidence

Sam confirms he is not running another SBC. The 27.0.41 diagnostic reports a local historical purchase record for Set 9 / Challenge 24 with one pending marker, two unconsumed purchase entries, two contributed items and one confirmed batch. Those are local journal states, not evidence of a task currently running at EA. The current SBC's confirmed score remains 11,680 / 50,000.

The old aggregate export still does not prove whether the historical request actually completed. This patch does not erase the marker, infer success, refund coins, consume its cards or restart that target. A deterministic production-composition test reproduced the real usability defect: unrelated stock-only recovery is blocked solely by the historical marker.

## Change

- Recover the current SBC's own original contribution journal, then inspect its remaining material scope under the existing shared lock.
- Allow continuation only for Club/Storage inventory, with no market route, purchase scope, purchase receipts or external-card moves. Exact physical item IDs must be disjoint from all historical reserved inventory/purchases and in-flight contribution material. Same-version other copies are not falsely blocked.
- Validate the historical contribution's frozen batch plan/material binding before using its scope. Unknown/malformed scope, the same physical card, missing current records and unresolved current contributions still block.
- Repeat the isolation check during fresh material validation and inside the native dispatch callback. A scope change after preview cannot authorize a contribution. Existing lock, evolution, active-squad, rule, score, context and exact-receipt checks remain intact.
- Restoration sends no EA purchase, move or contribution. A new trusted click continues only the original unconfirmed batches; confirmed batches remain disabled and skipped. The old purchase journal remains byte-for-byte unchanged, is not marked settled and gains no new approval.
- The panel calls the blocker a local historical record, not another currently running task. It displays the stored SBC name when available. Verified isolation gives a clear continuation message and retains confirmed points instead of telling the user to reopen an unrelated/expired SBC.

This is deliberately stock-only isolation, not a general override for unknown transactions. Purchase routes and overlapping material still require their own valid recovery. All 27.0.36–41 ordinary Puzzle, Gallery, progress-read and protection fixes are retained. No journal schema migration or automatic historical cancellation is introduced.

## Reservation and checkpoint lifecycle

Sam additionally reports that manually clearing a squad leaves cards reserved. The real native Puzzle-flow regression reproduces this: clearing removes the reservation index entry but retains the terminal concept draft for recovery; sibling-Challenge legacy migration then recreates the old reservation from that draft. The release now persists an empty-ref marker in the existing schema so migration does not resurrect it. A later confirmed save replaces the release marker normally. Terminal evidence, unrelated targets, pending saves and native server-baseline protections are preserved; no lock/evolution/rating or submission rule is loosened.

A separate production-composition regression reproduces orphan outer purchase markers after an inner contribution result is replaced. Before replacing that matching inner journal, the existing shared lock now synchronizes its outer bookkeeping from exact durable confirmed receipts, or clears only an intent whose inner result is positively unsent/rejected. Unknown/pending writes, missing receipts, changed scope or a failed local checkpoint prevent replacement rather than discarding the evidence. This prevents future proof loss; it does not reconstruct missing proof for an already-orphaned legacy record or mark an old SBC completed from its age.
