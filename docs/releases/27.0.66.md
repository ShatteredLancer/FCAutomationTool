# 27.0.66 — Handle Gallery scoring checkpoints without crashing roadmap progress

- Fixes a deterministic overall-planning exception: scoring may yield without a progress payload to keep the page responsive. Once that checkpoint crossed a time slice, the roadmap UI read `undefined.phase`. The cooperative runner now still schedules, enforces the deadline and checks cancellation, but only publishes actual progress records. Evaluation order, score rules and regular progress records are unchanged.
- Unexpected exceptions are reported as fixed classes such as `FC27_GALLERY_ROADMAP_TYPE_ERROR`, without exporting raw messages, stacks or account data. Error metadata that itself throws cannot prevent cleanup. Completed synchronization/pricing phases are no longer marked failed because a later step failed.
- Keeps fast Fodder forecasts, deep independent quotes, purchase-time checks, budgets, per-card limits, locks, collection history, pending transactions and cache TTLs unchanged. This is not a synchronization-performance redesign and does not skip collection verification.

Evidence: the supplied .65 diagnostic contains two forecast-only runs. Planning failed after 78/118ms, following 169,081/50,436ms of synchronization. The old 169-request quote failure was historical, not from these runs. The diagnostic did not export the underlying exception, so the deterministic scoring-checkpoint regression is not presented as an exact replay of all account inputs or the only possible live cause.

Verification: `npm run verify` passed with `VITEST_MAX_WORKERS=4` and the unchanged 10-second test timeout (436 files, 5,209 passed, 39 skipped). Root/dist/version and FSU assets match. Complete offline Chrome passed, including the new checkpoint reproduction, error-class privacy/cleanup, completed-phase status and existing quick/deep, expiry, cancellation/account-isolation and refresh-race scenarios.
