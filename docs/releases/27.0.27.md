# 27.0.27 — 已结清旧挂牌跨批重现修复

## 新诊断证据

27.0.26 的新诊断显示三次买断/入 Club 成功，累计花费 9,000；最后积分 17,210。
实际批准预算 37,950、剩余 28,950。另一版本的一次买断明确返回 HTTP 403 /
原生错误 461，不计入已花金额。最后一次查询仍返回三条挂牌，但在新的买断前停止于
`FC27_STREAMLINED_PURCHASE_OFFER_CHANGED`，不是总预算或 10 分钟授权耗尽。

原错误码同时覆盖版本、价格、物品身份及历史实体重复，诊断未导出实体/交易 ID，
故无法从文件逐项证明最后那条挂牌的具体冲突。已在真实采购 driver/Journal 中
复现同码路径：前一批已经买入并确认消耗的挂牌再次被原生搜索选中，旧代码将其
当作未确认身份冲突，要求恢复，尽管该次没有新买断。

## 修复边界

- 仅 Streamlined 在共享原生 buyer 选最低价前启用排除回调；只跳过 Journal 中
  **同版本 + 同 item ID + 同 trade ID** 且 `rejected` / `consumed` 的完整匹配。
- 已处理旧挂牌不再竞争最低价；同次搜索还有新实体时直接选新实体，不重复付款。
  全部结果均已处理时，按原有限缺货/换卡流程处理，不凭空创建未决成交。
- Driver 保留第二层检查；已结清完整匹配可跳过并在既有次数内再查。
  部分身份匹配、未结清实体、错误版本、无效物品/交易身份、超过限价仍停止。
- 补充固定原因 `definition` / `price` / `item` / `trade` / `record-identity`，
  以及 `offer-filter` 的 `skippedCount`。只输出原因/数量，不导出实体或交易 ID。
- 不改 Journal 格式、成交核对、已消耗积分、审批预算或已选库存范围；旧记录保留。
  15% 新方案建议预算、原最低材料价值目标、单卡冻结限价、原生节奏、锁卡/进化/
  主阵容保护、10 分钟授权和未知回执恢复均保留。
- Gallery/Puzzle 未启用排除回调，保留原选单；FSU 文件及原价格步进未改。

## 仍待观察

新日志的报价窗口耗时已用尽：149 个市场版本只有 8 个有效报价，库存报价有效
158 / 162。本轮只修复选单/历史重复；没有扩展用户已批准市场池或将缺价当零价。
因此当前方案不能被称为全市场最低价，报价覆盖不足仍在原界面提示。
