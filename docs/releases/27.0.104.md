# 27.0.104 — Streamlined 全流程恢复与防重放

## 整条链路复查

本次覆盖恢复原任务、识别已购材料、补买、移入 Club、分批贡献、回执持久化、进度回读、本地清理、完成及重载后的再次操作。修改前使用生产状态机和 Journal、合成原生响应复现缺口，不执行真实账号交易。

### 1. 拒绝批次增加材料后仍能继续

27.0.103 只允许同一 fingerprint 的明确拒绝单批次再执行。实际采购可能在原来2张未消费材料上增加新卡；新批次 fingerprint 改变，旧拒绝记录的材料重叠检查又阻断了贡献。

仅活动采购桥接允许替换这类单批次：同账号、完整 Challenge 合同、政策及已确认积分完全一致；旧状态必须 rejected、无成功回执、无积分漂移且 revision 匹配。先归档并回读旧记录，再 fresh 核验新批次。普通贡献、未知或已确认批次的重叠保护不放宽，外层新意图不被清掉。

### 2. 模糊买卡回包不再当成确定失败

共享原生买卡适配器以前把 success:false 全部视为未成交；500/503 等回包可能发生在服务端已扣款之后。采购据此替换挂牌会形成重复购买及漏记支出。

现在只有已审查的否定状态 400/401/403/404/409/429/461，且没有矛盾的 itemIds，才返回 rejected。服务错误、未知状态、格式异常或矛盾的物品证据返回 unknown，保留精确 buy-pending 意图。恢复只核对原 itemId/版本；确认持有后仅记一次原成交支出，不额外发起竞价。正面成功回执仍要求唯一精确物品匹配。

这一收紧作用于共享买卡入口；Gallery/Puzzle/Trading 的预算、授权及执行顺序不变，不新增自动重试权限。

### 3. Stop 覆盖等待窗口，不打断已发送请求的结算

- 采购适配器异步创建期间收到 Stop，新 driver 不再被启动。
- 写入贡献 pending 之后、进入 Provider 之前再次检查 Stop；未发送意图回到 waiting。
- Provider 创建传输、检查其他交易、读 Journal、标记页面缓存之后，都复核未发送的停止信号。
- 原生传输在异步 preflight 后及实际 send 前检查 Stop，避免微任务间隙漏发；确定取消回到 waiting/stopped。
- 已经发送的贡献仍完成回执、对账和本地结算，不因 Stop 抹掉消费证据或重新发送。

### 4. 已验证回执的一次本地存储失败可继续

仅对已经验证的 accepted 回执 checkpoint，允许一次本地 Journal 写入重试，沿用原 revision。绝不重试贡献请求。若首写其实已经成功，revision 冲突保护仍生效；若存储持续失败或服务端回执完全丢失，保留 pending/unknown 等待可靠证据，不根据积分变化猜成功。

## 完整合成路径与故障矩阵

使用事故形状的汇总起点：10,550/16,000分、已花3,500、批准预算8,568、6张历史已消费、2张已买未消费。所有卡身份、报价、候选和服务响应均为合成数据，不是用户现场冻结计划的精确重放。

完整生产组合经恢复、补买5张、移动、贡献、最终进度回读及页面维护后达到16,360分，总支出7,750；7张本轮材料的精确实体各消费一次，历史6张不再使用。新实例重载、恢复及重复执行不新增买入、移动或贡献。这是离线可重复性证明，不是用户账号已完成或当前市场供应的证明。

另覆盖：买卡响应丢失、移动响应丢失、贡献 accepted 后读回失败、页面维护前/后失败、内层确认后外层存储失败、完整贡献回包丢失、无供应、旧 pending/unknown 与新批次重叠、买入后停止、异步准备/发送前停止、服务错误/矛盾物品证据、本地回执持久化短暂/持续失败。可恢复证据沿原实体继续；不可判定的消费保持暂停。供给不足不通过提高原 cap 解决。
