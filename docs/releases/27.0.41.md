# 27.0.41 Streamlined recovery routing

## Observed incident

The supplied 27.0.40 diagnostic shows a new 34-stock-card / two-batch plan for the remaining 38,320 points of a 50,000-point SBC. The already-confirmed score is 11,680. Execution stops at preflight with `FC27_STREAMLINED_RECOVERY_REQUIRED`; two recovery clicks then return `FC27_STREAMLINED_OTHER_TARGET_PURCHASE_RECOVERY_REQUIRED`. No new contribution dispatch or progress-GET failure is recorded in this attempt.

The old export does not include the foreign purchase's target or settlement states. It therefore does not establish whether that particular record is safely settled or genuinely unresolved. Production-composition regressions reproduce both branches, without clearing records to bypass recovery.

## Changes

- Use the existing settlement predicate, not `completed`, to classify another SBC's purchase history. A stopped run with only waiting, rejected or consumed entries and no contribution-in-flight does not hijack recovery of the current SBC. The foreign journal remains unchanged and is not resumed or approved.
- Unknown buys/moves/contributions and purchased-but-unconsumed cards still block. Even `completed=true` does not bypass those states. Malformed or unreadable history still blocks.
- If a foreign purchase really needs recovery, independently recover/read the current SBC's contribution record for display. Keep its confirmed score visible, but create no executable preview and grant no purchase/move/contribution authority. Other-target records never become the current preview.
- Explain the foreign Set/Challenge and bounded pending-request/unconsumed-purchase counts in Chinese, and retain that evidence in diagnostics. The export contains no raw receipts, physical identities or account details.
- The generic contribution-recovery message now covers a partially confirmed old plan instead of incorrectly implying that its last submitted batch must still be unknown.

The existing old-plan recovery remains deliberate: confirmed batches are disabled and skipped; only a new trusted click can continue its remaining batches after fresh material/rule/protection validation. This patch does not replace a partially executed journal with a newly generated plan, cancel unknown transactions, extend budgets or resume another SBC automatically. All 27.0.36–40 fixes, Gallery, ordinary Puzzle and FSU behavior remain intact.

## Update

Install 27.0.41, refresh the Web App, open the current SBC and click **核对并恢复** first. Settled foreign history no longer interferes with restoring this SBC's original plan. If foreign transactions really remain unresolved, the panel identifies their target and counts while retaining the current SBC's confirmed score. Do not repeat confirmed batches or erase journals manually.
