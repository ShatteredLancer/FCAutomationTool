# 27.0.102 — Streamlined 已购材料恢复后续做

## 问题与证据

27.0.101 的两份连续诊断显示：前两批共6张贡献已确认，积分10,550/16,000、已花3,500金币。第三批遇到401。后续核对已经成功，未知请求归零，但2张已购材料仍未消耗；用户重新生成方案后，旧采购任务与新方案身份不同，继续被 `FC27_STREAMLINED_PURCHASE_RECOVERY_REQUIRED` 拦住。因此后一次停点不是仍有401，也不是计算未完成。

新增合成跨步骤回归使用真实 Session、Procurement 和 Purchase Journal，先确认6张、再保留2张已购卡，复现刷新/恢复后重新生成方案丢失任务身份；旧源码测试失败。仅重放流程形状，未导入用户库存、账号或交易实体。

## 修复行为

- 点击“生成方案”时，同账号、同Set/Challenge、同目标积分若还有未结采购任务，先复用原有完整只读恢复流程；不再建立冲突的新任务。不存在未结采购任务时，原规划路径不变。
- 恢复只核对EA状态并持久化本地证据，不购买、移动或贡献。界面保留原计划身份、材料范围、政策、累计支出、总预算及单卡上限；更改的规划设置不覆盖原任务。
- 恢复后明确显示已确认人数/积分、已购待处理人数、已花和剩余预算，以及“继续原方案购买并贡献”。继续仍需用户可信点击；已确认批次由原状态机跳过，已购卡先被核对和使用，仍需采购时按原授权池与上限重新核价。
- 未知请求、材料缺失、保护核验失败、账号/页面变化、损坏记录继续阻断；不删除、归档或伪造已完成证据，不在恢复失败后回退到新计划。
- 原30分钟执行窗口未改变，只修正文案仍写10分钟的情况。

## 影响面与验收

仅调整Streamlined规划/恢复入口与展示，共用原恢复实现；不修改采购、贡献、材料验证、FSU、锁卡/主阵容、预算、报价有效期及底层请求合同。保留ad的27.0.101 Puzzle优化、旧贡献归档与Gallery调查改动；交易功能不变。

真实账号验收：更新后刷新，进入原SBC点击“生成方案”或“核对并恢复”，应显示原任务及2张已购卡。确认继续后才执行；仍有认证失败或材料差异时停止。离线测试不代表已代用户完成该SBC。
