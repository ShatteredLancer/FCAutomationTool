# 27.0.35 — 完成归零后的核对不再只依赖次数加一

## 日志与原因边界

Viva 的 .34 方案是四张已有库存：三张 83 各 410 分、一张 63 铜卡 20 分，
合计 1,250 分；其中两张 83 来自 Storage。市场补卡数量为 0，铜卡的 200
是参考价，不能当成本次自动买断的证据。

EA 贡献响应和持久回执通过，随后反复返回 `CYCLE_RESET_UNVERIFIED`。
旧检查在完成回执后读到零分时，还要求子 Challenge 的完成次数严格增加 1。
此导出没有具体前后计数，因此只能确定旧证明条件不成立，不能断言现场
一定是字段缺失、计数未变或已经逐项确认目标分数。

匿名核对当前 EA 原生代码：完成会使可重复 SBC 的积分/状态归零；factory
直接投影 DTO 的 `timesCompleted`，不保证缺失值会被补为次数。已用公开
factory 源码及合成无账号依赖，重放计数 0 和缺失时的同码拦截。
