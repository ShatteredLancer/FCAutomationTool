# 27.0.68 — Separate read-only Gallery estimates from executable quote freshness

- Implements the explicitly confirmed behavior: the fast overall forecast captures a fresh Fodder reference at the beginning of the run. Its original fetch/expiry times remain intact, but expiry during synchronization, computation or same-page continuation no longer discards that read-only estimate. A reference already expired when capture is attempted is not accepted.
- The visible note updates its read time/expired-cache label while the dialog is open. Analysis JSON keeps `fresh:false`, original timestamps, `capturedAt` and `cacheExpired`; diagnostics distinguish a held estimate from a fresh quote. No estimate is inserted into a quote store, spending approval or GM snapshot.
- The boundary to a club still passes only Set ID and grade, never forecast prices. The original club/purchase price source, quote freshness, per-card/total caps, protections, transaction recovery and FSU behavior are unchanged. Deep independent quotes still expire normally, and account/catalog/material changes still invalidate the analysis.
- Fodder's five-minute cache and anonymous empty-collection requests are unchanged. This is not a synchronization-speed fix.

Evidence: .67 logged the configured 300,000ms planning limit, 228–231 seconds of prior synchronization and expiry after only 68–71 seconds of computation. The reduced diagnostic clock replay first reproduced the failure in production UI code, then verified the forecast-only fix with synthetic cards/rules and zero EA access. This is not a replay of private account cards or a live runtime benchmark.

Verification: `npm run verify` passed (437 files, 5,230 passed, 39 skipped; four workers and the unchanged 10-second test timeout), root/dist/version and FSU assets match. Complete offline Chrome passed, including nine clock scenarios: diagnostic-timed expiry, synchronization over five minutes, passive idle expiry, expired continuation/export/target-only handoff, initially expired input, fresh/expired independent deep quotes and account/material drift. No EA account or actual transactions were used.

Remaining acceptance items are recorded in [the implementation plan](../FC27_FODDER_REFERENCE_ZH.md). Live-account full-route completion and synchronization latency remain post-update checks; the user's installed page/settings were not changed during verification.
