# 27.0.94 — 配对保存反馈与免费连接检查

## 修复什么

27.0.93 的“保存采集器连接”存在两个界面问题：候选分析忙碌时，点击会被共用 busy 标志直接忽略；即使执行了保存，也会清空输入框并仅在页面顶部显示成功，当前配对区没有反馈。此外，原保存接口未回读存储验证，也未区分“保存配置”和“连通采集器”。

- 配对保存改为独立处理，不再被候选分析或公共查价挡住；自身防连点，显示正在处理。
- 成功、失败、未连接等结果直接显示在按钮旁并通过 `aria-live` 提示，不必翻到页顶找。
- 写入后回读确认；验证成功才清空输入框。重开交易页时只读本地配对保存状态，不会自动发网络请求或调用模型。
- 配对码格式错误、存储写失败、回读不一致、在线采集器拒码分别明确提示。在线拒绝的新码不覆盖已经保存的码；报错不显示实际配对码。
- 合法配对码在采集器离线时仍可保存，明确显示“已保存；未连接”，不声称已连通。

## 怎么看结果

升级油猴后，展开“连接本机采集器”。

1. 显示 **“配对码已保存（已回读）”**：不必重新粘贴，点击 **“检查连接（不采集）”**。
2. 显示 **“未配置配对码”**：只复制控制台冒号后的 48 位十六进制码，点保存。
3. **“配对码已保存；本机采集器已连接”**：保存及本机服务检查均通过，再按需点“采集 X 线索并筛选”。
4. **“已保存；未连接”**：在项目根目录的 PowerShell 运行 `npm.cmd run trading:intel` 并保持窗口开启；不需要修改 PowerShell 执行策略或管理员权限。
5. 提示 **“采集器版本较旧”**：在更新后的项目目录重启采集器，使新增状态接口生效。不会用一次付费采集代替连接检查。

本版仅新增认证后的固定 `POST /v1/status`，四秒连接检查不执行 Grok、不读取帖子、不消耗采集次数、不刷新消息缓存。原 `POST /v1/refresh` 仍仅由独立的显式采集按钮触发；保存和检查不触发它。
