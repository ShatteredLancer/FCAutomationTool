# FC Automation Tool 27.0.16

日期：2026-10-09。修复 Gallery 买入后核对接口不兼容造成的反复恢复阻断；FSU Local 保持 26.09.9。

## 原因与改动

- 27.0.15 用户诊断反复出现 `FC27_CLUB_RUNTIME_UNVERIFIED_METHOD_0_CHANGED`，每次均为买入 1 张、花费 1,100、完成核对 0 张。买入已成功，持有位置的核对未完成；没有重复扣款的证据。
- 上版仅补 `bid/move` 指纹，漏了 `locate()` 的 Club 读取依赖。即使本批去向为 Unassigned，恢复仍先查 Club，再核对 Unassigned 中的精确实体。
- 匿名读取 EA Web App build 11414，审查全部七个底层 HTTP 请求函数。按精确方法登记指纹，Club、Market 和通用请求校验共用同一份兼容表；没有放行未知包装或扩大 service/DAO 写方法许可。
- Gallery 初始化先验证完整核对依赖，不发送 Club 请求、不提前消费金币。遇到未知指纹在买入前停止；诊断包含允许的方法名与 SHA256，不含源码、账号或凭据。
- 保留原购买 Journal、冻结去向、价格上限和实际成交价。已有买入记录必须核对 `itemId + definitionId`，确认后继续；同版本另一张卡、缺失或歧义回执仍保留待核对，不重复买。

公开来源、独立审查与回归证据见 [工程记录](../REFACTORING_MILESTONES.md#2026-10-09-27016-gallery-成交核对与恢复)。旧七个函数的完整源码捕获在本机缺失，因此不宣称逐字解码等价；本次对当前公开源码独立检查请求构造、URL、请求体、发送与取消合同。

## 更新与恢复

从 [main 安装脚本](https://raw.githubusercontent.com/ShatteredLancer/FCAutomationTool/main/FCAutomationTool.user.js?v=27.0.16) 更新，刷新 Web App，核对版本 **27.0.16**。

回到原购买结果点击 **Check and continue**，先核对已买的那张卡。确认完成后，两张未买到的卡可另行调整价格并 **Retry selected**；不会替用户提高已批准价格。保留原记录，不清空 Journal、不重新创建整批。

本次离线验证不等于账号实买验收。没有代用户买卡、入库、挂牌、贡献或提交 SBC；没有创建 tag 或 GitHub Release。
