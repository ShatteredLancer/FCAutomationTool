# 27.0.65 — Keep Gallery forecasts fast and defer routine refresh races

- Fixes a reproduced `FC27_PUBLIC_PRICE_CONTEXT_CHANGED` path: during overall planning, the five-minute background catalog refresh could render a stale cached view before the identical catalog was revalidated, invalidating in-flight price reads. Routine catalog refresh and shared-cache polling/callbacks are deferred while the roadmap is busy and resumed afterwards. Explicit preparation, account checks and observed catalog/material changes still invalidate old inputs; validation is not bypassed.
- Following Sam's explicit choice, the **fast overall forecast now uses Fodder's per-version estimates without waiting for whole-catalog independent price reads**. Local rules and collection history are still verified. Forecast prices are not inserted into `freshPrices`, spending approvals or per-club quote stores. Conflicting public observations use the higher value consistently; missing values stay unknown. The underlying market observation time remains unknown.
- Entering a collection and actual purchasing retain the original independent price read, per-card ceiling, total budget and transaction/recovery logic. Deep optimization still uses independent quotes. If public references fail, fast mode reports the gap and offers deep optimization rather than silently initiating a slow whole-catalog quote run.
- The analysis JSON labels forecast values explicitly, with `fresh:false` and unknown market age. UI text distinguishes forecast pricing from purchasing authority. Roadmap phase durations, outcome and fixed mismatch classes now survive ordinary pool-log floods in the existing bounded performance ring; no account identities or raw payloads are added.
