# 27.0.84 — 大库存的完整材料价值比较

## 现场与证据边界

Viva .83 日志 Set76/Challenge116：库存填阵保存成功，初始与最终材料估值均11,250，耗时37,825ms，最后标记 `FC27_PUZZLE_VALUE_BASELINE_RETAINED`。用户确认没有购卡。该数字是材料估值，不是购卡支出；纯库存也不应被当成没有材料成本。

日志记录581项库存、过滤269项，库存估价批次请求250个版本；第一批报价耗时27,209ms。日志没有保留所选八张卡的完整事实，也缺失“保留库存方案”时的市场比较摘要，故不声称已重放Viva的真实阵容、证明现场唯一根因，或给出真实可节省金额。

## 确定的代码缺口与复现

1. `ownedValues` 原来最多估价250个版本。后续 `plan` 只要发现任意安全自有版本未估价，就把目标从整队材料价值降为新增购卡支出，自有卡在该目标下成本为0。即使所选方案的所有材料都有报价，比较结果仍没有材料价值，无法替换已估价库存基线。
2. 新的先红控制：250个安全版本时按材料价值比较；仅增加第251个无关版本，原代码变为 `additional-coins`。合成基线16,000，已知存在更便宜的原生合法资料组合；不是Viva逐卡/实时市场重放。
3. 原生入口还存在证据缺口：保留库存基线时提前返回，未保留市场比较摘要。先红入口测试确认 `procurementSummary` 与对应诊断缺失。

## 修改和保留边界

- 只有已提供合法材料基线金额时，才允许在已取得有效同源报价的候选子集中继续整队材料价值比较。未知价格自有卡从这次金额搜索中排除，不补0、不借另一来源价格，不因未查全部库存就放弃已知可比较组合。
- `unknownCount` 与 `scopeTruncated` 仍保留；结果不代表已覆盖全部库存或全市场最低。没有已估价基线的普通缺料流程，保留原现金可行性回退和“材料价值未知”状态。
- 每次公共估价仍最多250个版本，不改三页资料/原节点预算、报价TTL、预算或单卡限价。只有完整估值严格低于基线、同源且原基线仍有效，原生入口才选用替代组合；否则原方案保底。
- 未知/过期价格排除，未报价副本不充当免费卡。更贵的市场组合不替换原方案；锁卡、主阵容、FSU、预留材料与完整原生评分/默契/数量验证不变。
- 保留/改善纯库存方案时也保留原有格式的比较摘要，成功保存后进入现有诊断环；只含原有汇总字段，不增加原始库存/私有阵容导出、新GM键或交易权限。
- 不自动买卡、移动或提交；概念阵容后的购卡仍须原显式审批和独立核价。已有成交、未决记录、原采购预算和 .80–.83 的修复不改。
