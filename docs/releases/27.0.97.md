# 27.0.97 — 整理交易台，修复过期候选反复拦截

## 现场定位

本次 14:02 导出的 .96 日志中，13:51:26 已生成候选，13:59–14:01 八次生成清单均被 `DESK_DISCOVERY_EXPIRED` 拦住。候选五分钟有效期已过，但原按钮只报错，没有重新读取。

另有一份旧执行记录停在 `DESK_EXECUTION_READ_UNCONFIRMED`，汇总为已确认买入 0、待核对写请求 0。汇总数字不足以证明逐卡从未发送；新日志没有这次原生读取的 HTTP/响应细节，因此不把缺状态、缓存状态或 503 猜成根因，也不放宽读取成功条件。

## 流程修复

- 明确点击生成**整批新方案**时，如同账号候选过期或观察资金条件变化，最多重新分析一次，再显示新的可审核清单；不延长旧报价、不保留旧审批、不自动交易或采集 X。
- 移除候选的子集操作仍绑定原清单，过期时要求重新生成整批，不偷偷换回被移除的卡。取消、换号、更新候选或新 X 结果使旧异步计算失效。
- 只有逐条都是 `waiting + offer:null`，且没有任何额外交易证据的旧记录，才可在用户批准新方案时先完整归档并回读，再替换。从未发送以外的未知买入、转移、上架和持仓全部保持原阻断。
- 对严格未发送且停在读取未确认的记录，点击只读核对会实际重读原生状态；读成功才清除对应原因，不再“什么也没读就清空错误”。没有新增买/移/挂。
- 读取日志区分 Unassigned、Transfer、价格边界和售出回执阶段，并记录固定差异码及数值 HTTP/业务码。保持原严格回执合同，不记录实体/账号/配对码或原响应。
- 保持显式点击“采集 X 线索并筛选”后使用本次线索重新做一次有界公共候选筛选；新增检查避免界面整理意外触发双重分析，不增加模型调用、不设定时。

## 界面整理

交易台分为四个区：

1. **投资与执行**：新方案预算、整批清单、占用/情景净利、审核启动；已有执行显示逐卡状态和原始买价上限/挂牌目标。
2. **候选与线索**：公共候选和按需 X 采集。详细理由、退出规则折叠，不再重复铺满执行页。
3. **观察笔记**：提醒、观察名单和手填记录，明确不是自动交易回执。
4. **设置**：观察筛选/手填资金与采集器配对。真实执行预算仍在第一屏独立审核。

没有清单时隐藏审核/启动；无可继续操作的已上架持仓不展示“继续”，避免重复买挂误解。暂停原因用中文说明下一步，固定错误码折叠保留。继续旧方案时明确显示冻结的原总上限及留存，并提供可访问说明，上方输入只用于新方案。新草稿因已有持仓被拒时，只清未启动草稿并重置审批，恢复原方案的继续入口，不重复买入。子页签支持方向键、Home/End 和可见焦点，窄屏清单改为逐卡布局。
