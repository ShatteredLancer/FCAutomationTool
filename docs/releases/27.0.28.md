## 本版改进

- 原协作搜索使用 setTimeout(0) 让出执行。浏览器后台计时器可能被延迟，少量
  搜索节点也可能耗尽原时间上限。改为优先原生 scheduler.yield；缺少该 API 时
  用自己创建的 MessageChannel，完成/失败都关闭两端；两种 API 都缺少才用 timer。
  相关原生行为说明：[Chrome 后台计时器](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)、
  [scheduler.yield](https://developer.chrome.com/blog/use-scheduler-yield)。
- 只改变规划的协作让出方式，保持求解目标、候选池、评分、排名和原节点/状态/
  时间上限。交易等待节奏、报价截止、单卡限价、总预算和 10 分钟授权没有改。
- 不保证浏览器冻结标签页、系统休眠或网络中断后继续；不通过保活绕过浏览器策略。
  原日志不能区分后台调度、计算与其它回调耗时，因此新增 processingMs、
  schedulingMs 和 durationMs；不把调度等待从原搜索期限中扣除。
- 日志明确 initialScore / plannedScore / targetScore，保留旧 currentScore 字段兼容；
  规划分数不当作已提交积分。执行仍只认原生服务端回执/进度。
- 完成/恢复诊断增加 pendingWriteCount、unconsumedPurchaseCount、contributedCount、
  confirmedBatches 和 purchasesSettled。未决请求和已买但未消耗的卡单独计数；
  缺少或异常字段不制造全清零。只读统计不修改 Journal 或成交/献祭判断。

## 隐患与保留边界

| 项目 | 审查结论 |
| --- | --- |
| 锁卡/进化/主阵容 | 不放宽；已选库存和购入实体仍在物化/贡献前按原保护复核 |
| 旧挂牌与重复付款 | 27.0.27 的完整身份匹配排除继续保留；新交易不能复用已处理实体 |
| 跨 SBC | 完成旧目标不会自动授权新目标；新批准后先归档已结清旧记录，新目标只用新选材 |
| 恢复 | 未知买断/移动/贡献继续核对，不能通过删记录重跑；已完成同一审批不重复贡献 |
| 资金 | 新方案 15% 只是总预算预留，不提高单卡上限；本次实际用款在已批准额度内 |
| 最优性 | 完整报价不等于全市场最优，时间/节点/状态有限搜索仍只给最佳已知方案 |
| 未来运行 | EA 登录、接口变化、429、容量、真实缺货、冻结/休眠与期限到期仍可暂停 |
