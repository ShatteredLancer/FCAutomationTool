# 27.0.112 — 修复SBC买卡拒绝被误判为全局限流

## 现场证据

.111 新日志的 Campaign Mix Upgrade 已确认 27,810 / 40,000 分、5 批、37 张贡献，花费 4,000 / 19,263 金币；pendingWriteCount=0、unconsumedPurchaseCount=0、purchasesSettled=true。截图的“已消耗34张”指库存卡，不与总贡献37张混为一谈。

首个异常是一次 bid：HTTP 403、EA 业务码 461、明确 rejected。随后首次以及两次恢复都返回 FC27_MARKET_TRAFFIC_STOPPED，积分和支出不变。共用 traffic 的普通响应分类扫描到403就写入持久化 throttle；ad 的新交易任务已用两层 bid 分类，但共用的旧SBC买家没有显式启用这条已审查路径。

461只按现有已审查规则归为该笔竞购拒绝，不声称一定是被另一位玩家抢走；也不把所有403当作无货或可重试。

## 修复边界

- 共用 `fc27-puzzle-buy.js`（Puzzle/Gallery/Streamlined共用买家）在原有 raw bid envelope 上显式复用 `marketTaskBuyResponse`，不改ad新交易任务的分类算法，不推广到search/move/list等响应。
- 明确失败、没有矛盾itemIds、业务码匹配原生PERMISSION_DENIED且分类为offer-rejected时，返回原明确拒绝并按原有可选开关排除这一条精确挂牌。后续仍由原尝试次数、原搜索间隔、当前价格授权、余额与原预算决定是否继续；不是把拒绝当成交。
- 外层401/429不会被461掩盖。验证码458/459、业务限流、无解释403、矛盾的已获物品证据仍停止/保留unknown，不发送第二笔写入。
- 保留原拒绝/未知/确认Journal和回执，预算、单卡cap、报价TTL、锁卡/主阵容与贡献防重不变。**已保存的全局暂停不自动清除**，更新或刷新不等于恢复授权。

## 用户恢复步骤

1. 更新 .112，刷新EA页面。不要清缓存、交易Journal或重新从零做该SBC。
2. 若EA自己提示登录/验证码/市场限制，先处理原生提示；真实认证/限流保护保持。
3. 在FCAT“市场交易”页显式点击“解除全局暂停”；这不会自动重启旧交易任务。
4. 回原Campaign Mix Upgrade，点“核对并恢复”，确认仍是27,810分和4,000支出，再继续原方案。若原执行授权已过期，按界面重新确认剩余执行；不删除已确认记录、不重买/重投旧材料。
